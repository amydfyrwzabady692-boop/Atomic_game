# وینزون بت — ربات بازی‌های گروهی تلگرام

رباتی که به گروه‌های تلگرام اضافه می‌شود و مسابقه‌های گروهی برگزار می‌کند:
۱۸ بازی داخل خود گروه (از جمله شطرنج تصویری، پوکر، حکم چهارنفره‌ی تیمی، حکم سه‌نفره و دونفره، چهاربرگ و انفجار) و ۵ بازی آرکید به‌صورت Telegram Mini App،
به‌علاوه‌ی دوئل دونفره با حریف تصادفی. بازیکن‌ها با سکه وارد مسابقه می‌شوند و برنده‌ها سکه می‌برند.

**کیف پول:** شارژ سکه با کارت‌به‌کارت و رسید، فروش سکه (تسویه به کارت/شبا) و انتقال سکه بین کاربران؛
بررسی رسیدها و واریزها با مدیران ربات در پنل `/admin` است. همه‌ی جابه‌جایی‌های سکه اتمیک‌اند و در ledger
فقط‌افزودنی ثبت می‌شوند ([جزئیات](#کیف-پول-شارژ-فروش-و-انتقال)).

استک: Python 3.12 · Django 5 · PostgreSQL 16 · Redis · python-telegram-bot 21 (async) · Docker

## راه‌اندازی سریع با Docker

```bash
cp .env.example .env        # مقادیر را پر کنید (حداقل BOT_TOKEN و SUPERADMIN_IDS)
docker compose up -d --build
docker compose exec web python manage.py seed_content      # کلمات، سوال‌ها، پازل‌ها، فروشگاه
docker compose exec web python manage.py createsuperuser   # ورود به پنل ادمین
```

سرویس‌ها:

| سرویس | کار |
|---|---|
| `db` | PostgreSQL 16 |
| `redis` | وضعیت زنده، قفل‌ها و rate limit |
| `web` | پنل ادمین جنگو (`/admin/`) + صفحه و API مینی‌اپ (`/arcade/`) روی پورت ۸۰۰۰ |
| `bot` | ربات تلگرام (`python manage.py runbot`) |

سرویس `web` هنگام بالا آمدن `migrate` را اجرا می‌کند و `bot` بعد از سالم شدن آن شروع می‌شود.

## ساخت ربات در BotFather

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید و با `/newbot` ربات بسازید؛ توکن را در `BOT_TOKEN` بگذارید.
2. **Privacy Mode را خاموش کنید** تا ربات جواب بازیکن‌ها را در گروه ببیند:
   `/setprivacy` ← انتخاب ربات ← **Disable**.
   (اگر ربات قبلاً عضو گروهی بوده، یک بار حذف و دوباره اضافه‌اش کنید. ادمین کردن ربات در گروه هم همین اثر را دارد.)
3. `/setjoingroups` ← **Enable** تا بشود ربات را به گروه اضافه کرد.
4. آیدی عددی خودتان را (مثلاً از @userinfobot) در `SUPERADMIN_IDS` بگذارید.
5. برای بازی‌های آرکید، مینی‌اپ را هم ثبت کنید ([پایین‌تر](#مینیاپ-آرکید-https-و-دامنه)).

بعد ربات را به گروه اضافه کنید. هر بازیکن باید **یک بار در پیوی ربات `/start` بزند** (دکمه‌اش زیر پیام لابی هست).

## تنظیم `.env`

| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن ربات |
| `BOT_USERNAME` | یوزرنیم ربات بدون `@` (اختیاری؛ از تلگرام خوانده می‌شود) |
| `SUPERADMIN_IDS` | آیدی عددی سوپرادمین‌ها با ویرگول |
| `DATABASE_URL` | مثل `postgres://user:pass@db:5432/gamebot` |
| `REDIS_URL` | مثل `redis://redis:6379/0` (اگر خالی باشد fakeredis درون‌حافظه‌ای، **فقط توسعه**) |
| `WEBHOOK_URL` | خالی = polling. برای production آدرس عمومی HTTPS (ربات روی `WEBHOOK_PORT` گوش می‌دهد) |
| `WEBHOOK_SECRET` | رشته‌ی تصادفی برای مسیر و هدر webhook |
| `MINIAPP_SHORT_NAME` | نام کوتاه مینی‌اپ در BotFather |
| `MINIAPP_BASE_URL` | آدرس عمومی HTTPS سرویس `web` |
| `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS` | تنظیمات معمول جنگو |
| `OWNER_TG_ID` | آیدی عددی مالک ربات؛ همیشه مدیر است (پیش‌فرض همان مالک فعلی) |
| `TRANSFER_MIN_COINS` | حداقل سکه‌ی هر انتقال بین کاربران (پیش‌فرض ۱۰) |
| `GROUP_MESSAGES_PER_MINUTE` / `GROUP_EDITS_PER_MINUTE` | سقف ارسال پیام (۲۰، حد تلگرام) و سهمیه‌ی جدای ویرایش پیام (۴۰) در هر گروه |
| `TELEGRAM_PROXY` | فقط اگر سرور به `api.telegram.org` دسترسی ندارد (مثلاً سرور داخل ایران): `socks5://host:port` یا `http://host:port` |
| `GUNICORN_WORKERS` / `GUNICORN_THREADS` | پروسه‌ها و threadهای سرویس web (پیش‌فرض ۳ و ۸) |

**polling یا webhook؟** برای توسعه `WEBHOOK_URL` را خالی بگذارید. در production یک reverse proxy با TLS
(مثل Caddy یا nginx) جلوی پورت ۸۴۴۳ سرویس `bot` بگذارید و `WEBHOOK_URL=https://bot.example.com` بدهید.

## مینی‌اپ آرکید (HTTPS و دامنه)

بازی‌های آرکید داخل خود تلگرام باز می‌شوند و **به HTTPS و دامنه نیاز دارند**.

1. سرویس `web` (پورت میزبان `WEB_PORT`، پیش‌فرض ۸۱۲۰) را پشت یک دامنه با TLS قرار دهید، مثلاً `https://game.example.com`.
2. در BotFather: `/newapp` ← انتخاب ربات ← عنوان و توضیح ← آدرس وب‌اپ: `https://game.example.com/arcade/`
   ← نام کوتاه (مثلاً `arcade`). همین نام را در `MINIAPP_SHORT_NAME` بگذارید.
3. `MINIAPP_BASE_URL=https://game.example.com` و دامنه را به `ALLOWED_HOSTS` و `CSRF_TRUSTED_ORIGINS` اضافه کنید.

تا وقتی `MINIAPP_BASE_URL` یک آدرس `https://` نباشد، ربات بازی‌های آرکید را در منوی `/game` پیشنهاد نمی‌کند
(زیر منو می‌نویسد که بعد از راه‌اندازی مینی‌اپ فعال می‌شوند) و `/arcade` می‌گوید آرکید راه‌اندازی نشده است؛
۱۳ بازی داخل گروه بدون این تنظیم هم کار می‌کنند (حکم، حکم سه‌نفره و چهاربرگ فقط روی میز مینی‌اپ‌اند و تا آن موقع پیشنهاد نمی‌شوند). سوپرادمین همان‌جا راهنمای سه‌مرحله‌ای راه‌اندازی را می‌بیند.

فایل `telegram-web-app.js` از خود دامنه سرو می‌شود (نه telegram.org که برای کاربرانی که با پروکسی MTProto و بدون
VPN وصل‌اند فیلتر است و بدون آن صفحه‌ی بازی اصلاً بالا نمی‌آمد). اگر در BotFather آدرس اصلی دامنه
(`https://game.example.com`) هم ثبت شده باشد، لینک مسابقه درست به همان مسابقه می‌رسد.

در گروه دکمه‌ی `web_app` کار نمی‌کند؛ برای همین ربات دکمه‌ی URL با لینک مستقیم می‌فرستد:
`https://t.me/<bot_username>/<app_short_name>?startapp=<match_token>` و خود مینی‌اپ از `start_param` می‌فهمد
مربوط به کدام مسابقه است. تمرین آزاد (بدون سکه) با `/arcade` در پیوی و دکمه‌ی `web_app` باز می‌شود.

> **اگر دکمه‌ی «باز کردن صفحه‌ی شطرنج/بازی» فقط چت ربات را باز کرد:** یعنی مینی‌اپی با نام کوتاه
> `MINIAPP_SHORT_NAME` برای این ربات در BotFather ساخته نشده (یا نامش فرق دارد). یا با `/newapp` همان نام را بسازید،
> یا `MINIAPP_SHORT_NAME=` را خالی بگذارید و در BotFather ← Bot Settings ← **Configure Mini App** آدرس
> `https://game.example.com/arcade/` را به‌عنوان مینی‌اپ اصلی ربات ثبت کنید (لینک می‌شود `t.me/<bot>?startapp=<token>`).
> تا آن موقع زیر هر صفحه‌ی بازی دکمه‌ی پشتیبان «📱 صفحه باز نشد؟ از پیوی ربات باز کن» هست: پیوی ربات باز می‌شود و
> ربات دکمه‌ی `web_app` همان مسابقه را می‌فرستد که بدون تنظیم نام کوتاه هم کار می‌کند.

علاوه بر این، وقتی مسابقه‌ی آرکید یا شطرنج/دوز/پوکر شروع می‌شود، ربات به **پیوی هر بازیکن** یک دکمه‌ی `web_app`
مستقیم همان مسابقه می‌فرستد که به هیچ تنظیم BotFather وابسته نیست. کسی هم که هنوز ربات را استارت نکرده و «شرکت»
را می‌زند، با همان لمس به پیوی ربات می‌رود و بعد از Start خودکار عضو همان مسابقه می‌شود (`/start join_<id>`).

منوی ساخت بازی (`/game`) اگر سازنده ۳۰ ثانیه دکمه‌ای نزند پاک می‌شود؛ هر کلیک زمان را از نو شروع می‌کند.
وقتی لابی ساخته شد، پیام‌های مسابقه تا پایان و اعلام برنده و سکه‌ها پاک نمی‌شوند و مسابقه‌ی شروع‌شده از داخل گروه
(نه با دکمه‌ی لغو و نه با `/cancel`) لغو نمی‌شود؛ فقط پنل ادمین یا خروج ربات از گروه آن را لغو می‌کند.

**توسعه‌ی محلی با تونل:**

```bash
python manage.py runserver 8000
cloudflared tunnel --url http://localhost:8000     # یک آدرس https موقت می‌دهد
```

آدرس تونل را در `/newapp` (یا `/myapps` ← Edit) و `MINIAPP_BASE_URL` بگذارید.
برای دیدن صفحه‌ی بازی در مرورگر معمولی بدون تلگرام: `DEBUG=True` و `ARCADE_DEV_AUTH=True` و سپس
`http://localhost:8000/arcade/?dev_user=1` (هرگز در production روشن نکنید).

## دستورات ربات

**پیوی:** `/start` · `/wallet` (کیف پول) · `/transfer` · `/duel` · `/me` (پروفایل) · `/daily` (گردونه‌ی روزانه) · `/invite` (دعوت دوستان) · `/support` · `/shop` (فروشگاه ظاهری) ·
`/history` (۲۰ تراکنش آخر) · `/arcade` (تمرین آزاد) · `/gtop` (رتبه‌بندی سراسری) · `/help`

**گروه:** `/game` (ساخت مسابقه) · `/top` (امروز / هفته / کل) · `/me` · `/rules` (قوانین کلی و قوانین هر بازی) ·
`/cancel` (سازنده یا ادمین، فقط قبل از شروع مسابقه)

`/start` در پیوی یک منوی دکمه‌ای هم می‌فرستد (افزودن ربات به گروه، جایزه‌ی روزانه، پروفایل، تمرین آرکید، فروشگاه،
دعوت، قوانین، راهنما)؛ هر دکمه همان کار دستور هم‌نامش را می‌کند.

**ادمین گروه:** `/settings` — فعال/غیرفعال کردن بازی‌ها، حداقل و حداکثر ورودی،
اجازه‌ی ساخت بازی به همه و روشن/خاموش کردن پیام دعوت به بازی در همان گروه. ادمین بودن در هر کلیک با `getChatMember`
بررسی می‌شود و هر کلیک فقط ستون همان تنظیم را زیر قفل ردیف ذخیره می‌کند.

**مدیران ربات:** `/admin` (پنل مدیریت داخل تلگرام؛ هر بخش طبق دسترسی همان مدیر) · `/grant <آیدی یا @username> <مقدار>` · `/ban` · `/unban` · `/broadcast <متن>` (یا ریپلای روی یک پیام) · `/stats` · `/backup`

### چرخه‌ی مسابقه

`/game` ← انتخاب بازی ← ورودی (رایگان تا ۱۰۰۰ سکه، در محدوده‌ی گروه) ← تقسیم جایزه ← **لابی** (زمان ثبت‌نام همه‌ی لابی‌ها ثابت ۱ دقیقه و ۳۰ ثانیه است: `LOBBY_JOIN_SECONDS`؛ اگر ظرفیت زودتر پر شود بازی همان لحظه شروع می‌شود)
(لیست زنده‌ی بازیکن‌ها، pot و زمان باقی‌مانده) ← اجرا ← رتبه‌بندی و پرداخت.

منوی `/game` همه‌ی بازی‌ها را روی یک صفحه ولی **مرتب بر اساس نوع** نشان می‌دهد: ♟ فکری و کارتی (شطرنج، پوکر، دوز، دوز
چهارتایی)، 🧠 کلمه و اطلاعات، ⚡️ سرعت و شانس و 🕹 آرکید؛ هر دسته یک ردیف عنوان دارد که با زدنش توضیح کوتاهی می‌آید
(`bot/handlers/flow.py`: `MENU_SECTIONS`؛ بازی تازه خودکار در «بازی‌های دیگر» می‌آید). هر مرحله‌ی بعدی شماره‌ی مرحله
(«مرحله‌ی ۳ از ۴») و خلاصه‌ی انتخاب‌های قبلی (کنترل زمان، ورودی، تقسیم) را بالای پیام نشان می‌دهد.

- بازیکن کافی نیاید یا مسابقه لغو شود ⇒ **برگشت کامل ورودی‌ها**.
- **هر تعداد مسابقه‌ی هم‌زمان در هر گروه:** هر کس هر چند بازی بخواهد می‌سازد؛ مسابقه‌ها با شناسه‌ی خودشان (`MatchManager.matches`) جدا اجرا می‌شوند، دکمه‌ها شناسه‌ی مسابقه را دارند و پیام هر بازیکن به همه‌ی بازی‌های متنی‌ای می‌رسد که در آن‌ها بازی می‌کند. `/cancel` لابی‌های خود فرستنده را لغو می‌کند (ادمین: همه‌ی لابی‌ها؛ ریپلای روی یک لابی: فقط همان).
- بعد از ری‌استارت: لابی‌ها و مسابقه‌های آرکید ادامه پیدا می‌کنند؛ بازی متنیِ نیمه‌کاره لغو و ورودی‌ها برمی‌گردد. هیچ سکه‌ای گم نمی‌شود.

**ترتیب کارت‌های دست:** در حکم، حکم سه‌نفره و چهاربرگ کارت‌های دستت از راست به چپ بر اساس بزرگی چیده می‌شوند:

اکثر بازیکن‌ها، گفت‌وگوی آن میز تا پایان همان بازی برای همه بسته می‌شود (`POST /arcade/api/board/chat_lock`، رأی‌ها و قفل
در Redis با `chat:lockvote:{room}` و `chat:locked:{room}`؛ نوشتن در اتاق قفل‌شده خطای `chat_locked` می‌دهد).

نمد شرابی‌بنفش دارد، کارت‌هایی که برداشته می‌شوند به سمت برداشت‌کننده پرواز می‌کنند و «سور» جشن کوچکی دارد.

**گرافیک میزها (نسخه‌ی باکیفیت):** میز حکم و چهاربرگ لبه‌ی چوبی براق با رگه‌ی چوب (نویز SVG) و نوار برنجی دارند؛ نمد همه‌ی

مبلغ را دقیق تایپ کن، با − و + (به اندازه‌ی بلایند بزرگ) یا نوار لغزنده تنظیم کن یا از «حداقل، ½ پات، ¾ پات، پات، آل‌این»
بردار و «تأیید» بزن (مبلغ بیرون از محدوده فرستاده نمی‌شود). وقتی نوبت دیگری است حرکت از پیش (چک/فولد، کال، کال هر مبلغ)
هست. «💬» گفت‌وگوی میز است (پیام بالای صندلی گوینده هم دیده می‌شود؛ تماشاچی فقط می‌خواند) و «🚪» قبل از بلند شدن ژتون‌ها و
سهم سکه را نشان می‌دهد. در پایان، سکه‌ی دقیقی که به هر نفر رسیده نشان داده می‌شود.

**میزهای چندنفره** (حکم ۴ و ۳ نفره، `duels.TABLE_SIZES`): جستجو تا پر شدن میز ادامه دارد؛ منتظرهای همان بازی با همان سکه
(و کسانی که «فرقی نمی‌کند» زده‌اند و سکه‌اش را دارند) جمع می‌شوند و با نفر آخر میز بدون توافق شروع می‌شود؛ صندلی‌ها و
یارها تصادفی‌اند، حکم‌ها ۳ امتیازی‌اند، هر کس پیام شروع با دکمه‌ی میز را در پیوی می‌گیرد و پایان بازی و جایزه هم همان‌جا
اعلام می‌شود (`DuelRunner.tables`). حکم دونفره، چهاربرگ و انفجار در حریف تصادفی کوتاه‌اند (۳ امتیاز، یک دست، ۳ دور).

#### دوئل دونفره

از پیوی ربات (`/duel` یا دکمه‌ی «⚔️ حریف تصادفی») یا تب «حریف» مینی‌اپ:

1. بازی را انتخاب کن — چهار بازی نوبتی (شطرنج، پوکر، دوز، دوز چهارتایی) یا هر کدام از ۵ بازی آرکید فعال (رکوردی: هر دو همان
   مرحله با همان بذر، ۳ دقیقه و ۲ تلاش، امتیاز بیشتر برنده) — و مقدار سکه را: بدون سکه، یک مقدار آماده، مقدار دلخواه یا
   «فرقی نمی‌کند».
2. ربات با کسی جفتت می‌کند که همان مقدار را خواسته یا «فرقی نمی‌کند» گفته (جستجو حداکثر ۵ دقیقه).
3. هر دو طرف پیشنهاد می‌دهند یا پیشنهاد حریف را قبول می‌کنند؛ وقتی دو پیشنهاد یکی شد بازی شروع می‌شود
   (اگر هر دو از اول همان مقدار را خواسته باشند بلافاصله). ۲ دقیقه برای توافق؛ بعد دوئل لغو می‌شود.
4. ورودی هر دو از مسیر ledger کم می‌شود (اگر یکی کم داشته باشد از هیچ‌کس چیزی کم نمی‌شود)، بازی روی صفحه‌ی
   همان بازی در مینی‌اپ است و برنده کل جایزه را می‌برد (مساوی نصف‌نصف)؛ در پوکر (میز نقدی) هر کس به اندازه‌ی ژتونش
   می‌برد. دوئل بدون سکه امتیازی ندارد.
5. دو حریف از لحظه‌ی توافق تا پایان بازی با هم **گفت‌وگو** می‌کنند (`arcade/chat.py`: پیام کوتاه، بدون لینک و
   @یوزرنیم، حداکثر یک پیام در هر ثانیه و نیم). توافقِ تاریخ‌گذشته همان لحظه‌ای که مینی‌اپ آن را می‌خواند بسته می‌شود،
   حتی اگر کار دوره‌ای ربات چند ثانیه عقب باشد.

ربات هر ۲ ثانیه دوئل‌ها را بررسی می‌کند (`bot/duels.py`): پیام هر دو طرف همیشه به‌روز است، چه حرکت از ربات باشد
چه از مینی‌اپ، و نتیجه و جایزه در پیوی اعلام می‌شود. حریف تصادفی به مینی‌اپ (HTTPS) نیاز دارد.

### صفحه‌ی اصلی مینی‌اپ

**خرید سکه در فروشگاه مینی‌اپ:** بالای تب «🛍 فروشگاه» بسته‌های ۵۰، ۱۰۰، ۲۰۰ و ۵۰۰ سکه با همان قیمت و کارمزد منوی شارژ
ربات (`wallet.services.TOPUP_PACKAGES` و `topup_quote`) و دکمه‌های «مقدار دلخواه» و «فروش سکه» آمده است. زدن هر بسته پیوی
ربات را با `/start topup_<تعداد>` باز می‌کند و همان لحظه شماره کارت و مبلغ دقیق را می‌دهد و منتظر رسید می‌ماند؛ یعنی پرداخت،
رسید و تأیید مدیر دقیقاً همان مسیر کیف پول ربات است. بدون شماره کارت در پنل، خرید غیرفعال نشان داده می‌شود. دسته‌های
خالی آیتم‌های ظاهری نشان داده نمی‌شوند (آیتم‌ها را از پنل جنگو اضافه کنید).

`/arcade/` حالا یک هاب کامل است با تب‌های: **بازی‌ها** (تمرین آرکید و شطرنج با کامپیوتر)، **حریف** (حریف تصادفی)،
**رتبه‌ها** (امروز/هفته/همیشه)، **فروشگاه** (خرید و فعال‌کردن آیتم‌های ظاهری) و **من** (آمار، نشان‌ها، رکوردها،
لینک و پیشرفت دعوت، تاریخچه‌ی تراکنش‌ها). اگر جایزه‌ی روزانه در پنل روشن باشد کارتش هم نشان داده می‌شود.

## اقتصاد سکه و قوانین تراکنش

- منابع سکه از **پنل ادمین ← تنظیمات اقتصاد سکه** تنظیم می‌شوند (پیش‌فرض‌ها داخل پرانتز):
  - **هدیه‌ی ثبت‌نام** (۰ = خاموش).
  - **جایزه‌ی روزانه** و سکه‌ی نجات (خاموش). وقتی روشن شود، دکمه‌ی «جایزه‌ی روزانه» در منوی پیوی
    ظاهر می‌شود و مقدارها همان `DAILY_*` و `RESCUE_AMOUNT` در `config/settings.py` است.
  - **دعوت دوستان:** هر `referral_every` دعوت موفق (۱۰)، `referral_reward` سکه (۳). دعوت وقتی «موفق» است که
    دعوت‌شده اولین بازی **سکه‌ای**‌اش را تمام کرده و حسابش ۲۴ ساعته شده باشد. هر دسته فقط یک بار پرداخت می‌شود.
  - دستاوردها و هدیه‌ی سوپرادمین/پنل مثل قبل.
- **بازی رایگان** (ورودی صفر): نه سکه، نه XP، نه برد، نه دستاورد و نه رتبه‌بندی؛ فقط برای سرگرمی.
  در منوی ساخت بازی، با انتخاب «رایگان» مرحله‌ی تقسیم جایزه حذف می‌شود.
- هر تغییر موجودی **فقط** از `wallet.services.apply_transaction(user, amount, type, idempotency_key, match=None)`:
  اتمیک، با `select_for_update` روی ردیف کاربر، هرگز منفی نمی‌شود (چک کد + `CHECK constraint`)،
  و `idempotency_key` یکتا جلوی کسر/پرداخت تکراری (کلیک دوباره، retry) را می‌گیرد.
  اگر همان کلید برای کاربر، مقدار یا نوع دیگری دوباره بیاید `IdempotencyConflict` می‌دهد (به‌جای نادیده گرفتن بی‌صدا).
- ledger (`CoinTransaction`) فقط اضافه می‌شود؛ ویرایش و حذف در مدل و پنل ادمین بسته است.
- جایزه‌ی دعوت فقط یک بار و همان لحظه‌ی استارت دوست پرداخت می‌شود (هر `referral_every` نفر، `referral_reward` سکه).
- جایزه‌ی روزانه یک گردونه است: ۶۹٪ پوچ، ۲۰٪ یک سکه، ۱۰٪ دو سکه، ۱٪ ده سکه (از پنل `/admin` روشن/خاموش می‌شود).
- حسابرسی کامل سکه: جمع ledger هر کاربر با موجودی‌اش، حساب هر مسابقه (ورودی‌ها = پات = جایزه‌ها، یا برگشت کامل در
  لغو) و هر رسید شارژ و درخواست فروش (دقیقاً همان تراکنش‌هایی که وضعیتش می‌گوید). اگر چیزی جور نباشد با کد خطا تمام
  می‌شود؛ همین گزارش در پنل `/admin` ← «حسابرسی» هم هست:

```bash
python manage.py audit_wallets
```

مقادیر اقتصاد در `config/settings.py` قابل تنظیم‌اند.

## کیف پول: شارژ، فروش و انتقال

همه از `wallet/services.py` می‌گذرند و هر کدام فقط یک بار اثر دارند:

- **انتقال (`/transfer`):** در گروه با ریپلای (`/transfer 50`) یا با آیدی (`/transfer @user 50`)، در پیوی از کیف پول.
  همیشه یک دکمه‌ی تأیید (۲ دقیقه اعتبار) دارد که فقط فرستنده می‌تواند بزند؛ توکن همان دکمه کلید یکتای ledger است،
  پس دوبار زدن، تحویل دوباره‌ی کلیک یا ری‌استارت ربات سکه را دوبار جابه‌جا نمی‌کند. هر دو کاربر به ترتیب شناسه
  قفل می‌شوند (انتقال‌های هم‌زمانِ برعکس بن‌بست نمی‌شوند). موجودی فرستنده در گروه نشان داده نمی‌شود.
- **شارژ:** کاربر بسته یا تعداد دلخواه (حداکثر ۱۰۰٬۰۰۰ سکه) را انتخاب می‌کند، مبلغ با کارمزد را کارت‌به‌کارت
  می‌کند و عکس رسید را می‌فرستد. هشدار با عکس رسید برای همه‌ی مدیران می‌رود؛ تأیید یا رد دو مرحله‌ای است و زیر
  قفل ردیف درخواست انجام می‌شود، پس اگر دو مدیر هم‌زمان کلیک کنند فقط اولی اثر دارد و پیام هشدار همه‌ی مدیران به‌روز می‌شود.
- **فروش:** شماره کارت ۱۶ رقمی (با بررسی Luhn برای گرفتن غلط تایپی) یا شبای IR و نام صاحب حساب گرفته و یک بار
  برای تأیید نشان داده می‌شود؛ بعد کسر سکه و ثبت درخواست در یک تراکنش انجام می‌شود. مدیر «واریز شد» (با یا بدون
  رسید بانکی) یا «رد و برگشت سکه» را می‌زند؛ هیچ درخواستی هم واریز و هم برگشت نمی‌خورد.
- **پنل `/admin` (فقط مدیران، هر بخش طبق دسترسی):** رسیدها و فروش‌های در انتظار، کارت کاربر (جست‌وجو با آیدی یا
  @username، دادن/کم کردن سکه با دکمه‌ی تأیید یک‌بارمصرف، مسدود/آزاد، پیام)، روشن/خاموش کردن هر بازی، مسابقه‌های در
  جریان (با لغو و برگشت ورودی‌ها)، کارت واریز، نرخ، هدیه‌ی شروع و دعوت، جایزه‌ی روزانه، آمار، **حسابرسی سکه** (همان
  `audit_wallets`)، مدیران و نقش‌ها، پیام به کاربر و پیام همگانی (با تأیید قبل از ارسال).

## جوین اجباری و API ربات‌های دیگر

- **جوین اجباری:** `/admin` ← «📢 جوین اجباری» ← «➕ افزودن کانال» (اول ربات را در کانال ادمین کنید؛ یوزرنیم، لینک،
  آیدی عددی یا یک پیام فورواردشده از کانال را بفرستید). تا کاربر عضو کانال‌های فعال نشود، پیوی ربات، «شرکت» و ساخت
  مسابقه در گروه و مینی‌اپ پیام عضویت با دکمه‌ی هر کانال و «✅ عضو شدم» نشان می‌دهند؛ کاری که کاربر می‌خواست (دعوت،
  شرکت در همان مسابقه، بخش کیف پول) بعد از تأیید ادامه پیدا می‌کند و هدیه‌ی ثبت‌نام و جایزه‌ی دعوت هم بعد از عضویت داده
  می‌شود. مدیران ربات مستثنا هستند و اگر عضویت معلوم نشود (ربات ادمین نیست یا تلگرام جواب نمی‌دهد) کسی گیر نمی‌افتد.
  عضویت با getChatMember پرسیده و در Redis کش می‌شود (عضو ۱۰ دقیقه، غیرعضو ۱۵ ثانیه) و ورود و خروج کاربر در کانال‌هایی که
  ربات ادمینشان است (رویداد `chat_member`) همان لحظه کش را درست می‌کند.
- **API برای ربات‌های دیگر:** رباتی که استارت این ربات یا عضویت یک کانال را جوین اجباری گذاشته، با کلیدی که از
  `/admin` ← «🔗 API اتصال به ربات‌های دیگر» ساخته می‌شود (همان‌جا راهنمای قدم‌به‌قدم، متن آماده برای صاحب ربات دیگر با
  لینک `?start=partner` و «🔍 بررسی یک کاربر» با آیدی عددی هست) از `https://<دامنه>/api/v1/user` و `/check` می‌پرسد کاربر ربات را استارت کرده
  (و بلاکش نکرده) یا عضو کانال‌ها شده است، و اگر وب‌هوک بدهد رویدادهای start، block، unblock، join و leave را همان لحظه با
  امضای HMAC می‌گیرد. جزئیات و نمونه‌ی PHP/Python: [`docs/forced-join-api.md`](docs/forced-join-api.md). پرامپت آماده برای
  وصل کردن ربات طرف مقابل: [`docs/antigravity-partner-bot-prompt.md`](docs/antigravity-partner-bot-prompt.md).

## دعوت به بازی در گروه‌ها و پست‌های آماده‌ی کانال

- **پیام دعوت هر ۲ ساعت:** ربات در هر گروه فعال یک پیام کوتاه و بی‌صدا («بازی کن، سکه ببر») با دکمه می‌فرستد:
  «🎮 ساخت بازی» (منوی `/game` را همان‌جا برای کسی که زد باز می‌کند)، «📖 راهنما» (توضیح کوتاه در پنجره‌ی هشدار)،
  و لینک‌های مینی‌اپ، حریف تصادفی، جایزه‌ی روزانه و کیف پول که پیوی ربات را در همان بخش باز می‌کنند (`?start=duel` و …).
  نُه متن چرخشی دارد (`core/texts.py`: `PROMO_VARIANTS`؛ تعداد بازی‌ها موقع ارسال پر می‌شود) و پیام دعوت قبلی همان گروه
  پاک می‌شود تا گروه شلوغ نشود. گروهی که همین حالا مسابقه دارد رد می‌شود و گروهی که ربات را بیرون کرده غیرفعال می‌شود.
  ادمین هر گروه با `/settings` خاموشش می‌کند (آخرین پیام دعوت همان لحظه پاک می‌شود) و مدیران ربات از `/admin` ←
  «📣 تبلیغ و کانال»: روشن/خاموش، فاصله (۲ ساعت پیش‌فرض؛ ۳، ۴، ۶ ساعت یا ۵ تا ۶۰ دقیقه)، پیش‌نمایش و «ارسال همین حالا».
  هر دقیقه بررسی می‌شود و ارسال زمان‌بندی‌شده و دستی یک قفل Redis مشترک دارند، پس هیچ گروهی دو پیام هم‌زمان نمی‌گیرد
  (`bot/handlers/promo.py`). مهاجرت `wallet 0012` فاصله‌ی سرورهای قبلی را هم روی ۲ ساعت می‌گذارد.
- **پست‌های آماده‌ی کانال:** هفت پست راهنما (معرفی، بازی گروهی، مینی‌اپ، شطرنج و پوکر، خرید و فروش سکه، بازی جوانمردانه،
  پرسش‌های رایج) با دکمه‌های لینک‌دار به بخش‌های ربات. از `/admin` ← «📣 تبلیغ و کانال» ← «📰 پست‌های آماده‌ی کانال»
  هر پست دیده و با یک دکمه در کانال‌های جوین اجباری یا هر کانال دیگر (با یوزرنیم یا آیدی) منتشر می‌شود؛ ربات باید در آن
  کانال ادمین با اجازه‌ی ارسال باشد. عددها (قیمت سکه، کارمزد، حداقل فروش، تعداد بازی‌ها) از تنظیمات همان لحظه خوانده
  می‌شوند. نسخه‌ی متنی برای کپی دستی: [`docs/channel-posts.md`](docs/channel-posts.md) یا
  `python manage.py channel_posts --bot <یوزرنیم>`.

## ضدتقلب بازی‌های آرکید

کد سمت کلاینت قابل دستکاری است، پس **امتیاز هرگز از کلاینت پذیرفته نمی‌شود**:

1. `initData` تلگرام با HMAC و `BOT_TOKEN` اعتبارسنجی می‌شود (`arcade/auth.py`).
2. سرور برای هر تلاش یک session یک‌بارمصرف با seed و زمان شروع صادر می‌کند.
3. کلاینت **لاگ ورودی‌ها** (زمان هر تپ/حرکت به میلی‌ثانیه) را می‌فرستد.
4. سرور همان بازی را با همان seed در پایتون **دوباره شبیه‌سازی** می‌کند (`arcade/sim/<game>.py`) و امتیاز را خودش حساب می‌کند.
   منطق هر بازی قطعی است: گام زمانی ثابت، فقط محاسبات عدد صحیح، و RNG سیدشده‌ی mulberry32 که در JS و Python یکسان است.
5. بررسی‌های معقول بودن: طول بازی از زمان واقعی سپری‌شده بیشتر نباشد (ردّ لاگ‌های آفلاین)، تپ‌های سریع‌تر از حد
   انسانی (فاصله‌ی کمتر از ۵۰ms)، ساختار لاگ، مهلت مسابقه و تعداد تلاش.
6. موارد مشکوک در پنل ادمین (جلسه‌های آرکید ← فیلتر «مشکوک») فلگ می‌شوند.

محدودیت صادقانه: کسی که کد بازی را بخواند می‌تواند رباتی بنویسد که لاگ ورودیِ «معتبر و انسانی‌نما» بسازد.
بررسی‌های بالا این کار را سخت و قابل‌ردیابی می‌کنند ولی غیرممکن نه؛ برای مسابقه‌های مهم جلسه‌های فلگ‌شده را مرور کنید.

## پنل ادمین

### نقش‌ها و دسترسی مدیران ربات

مالک ربات (`OWNER_TG_ID`) و `SUPERADMIN_IDS` همه‌ی دسترسی‌ها را دارند. بقیه‌ی مدیران را مالک از پنل `/admin` ← «مدیران»
(یا `/admin/` جنگو ← «مدیران ربات») با یکی از نقش‌های آماده یا دسترسی دلخواه اضافه می‌کند:

| دسترسی | چه چیزی را باز می‌کند |
|---|---|
| `payments` | رسیدهای شارژ و درخواست‌های فروش (و هشدار آن‌ها) |
| `coins` | دادن و کم کردن سکه (`/grant` و کارت کاربر) |
| `users` | جست‌وجوی کاربر، مسدود/آزاد کردن |
| `support` | پیام‌های پشتیبانی و پیام به کاربر |
| `games` | روشن/خاموش کردن بازی‌ها و لغو مسابقه‌های در جریان |
| `broadcast` | پیام همگانی |
| `settings` | کارت واریز، نرخ، هدیه‌ها، جایزه‌ی روزانه، کانال‌های جوین اجباری |
| `stats` | آمار و حسابرسی سکه |
| `admins` | فقط مالک: افزودن و ویرایش مدیران، کلیدهای API ربات‌های دیگر، و `/backup` (پشتیبان کامل اطلاعات کاربران) |

**👥 گروه‌های ربات:** `/admin` ← «👥 گروه‌های ربات» (دسترسی `stats`) فهرست گروه‌هایی است که ربات در آن‌هاست: فعال و
خارج‌شده جدا، به ترتیب آخرین مسابقه، با تعداد مسابقه‌ی این هفته و روشن بودن پیام دعوت. جزئیات هر گروه زنده از تلگرام
خوانده می‌شود (تعداد عضو، ادمین بودن ربات، یوزرنیم) و با دسترسی `settings` می‌شود ربات را بعد از تأیید از گروه بیرون برد.

نقش‌های آماده: «مدیر کامل» (همه به‌جز `admins`)، «مالی» (پرداخت‌ها، سکه، آمار)، «پشتیبانی» (پشتیبانی، کاربران،
پرداخت‌ها)، «ناظر بازی‌ها» (بازی‌ها، کاربران، آمار) و «فقط آمار». مدیران اضافه‌ی قدیمی (فیلد تنظیمات اقتصاد) با مهاجرت `core 0005` به
«مدیران ربات» با دسترسی کامل منتقل می‌شوند. هر دکمه و دستور دسترسی را دوباره بررسی می‌کند.

### پنل جنگو

`/admin/` — کاربران (مسدود/آزاد)، گروه‌ها، مسابقات (با اکشن **«لغو مسابقه و برگشت ورودی‌ها»**)،
ledger فقط‌خواندنی، بانک سوال/کلمات/پازل ایموجی/جمله‌های تایپ با **Import از CSV**، فروشگاه، دستاوردها،
جلسه‌ها و رکوردهای آرکید، و **داشبورد آمار** (`/admin/dashboard/`: کاربران فعال روزانه، بازی‌ها به تفکیک نوع،
محبوب‌ترین بازی، گروه‌های فعال).

- صفحه‌ی هر کاربر فقط **۳۰ تراکنش آخر** را نشان می‌دهد (با لینک «همه‌ی تراکنش‌ها»)، تا برای کاربرهای پرکار کند نشود.
- اکشن **«شارژ اعتبار مجازی»** دکمه‌های مقدار آماده و پیام تأیید دارد، همه‌ی کاربران را یک‌جا (همه یا هیچ) شارژ
  می‌کند و هر فرم یک کد یکتا دارد؛ دوبار کلیک یا رفرش صفحه دوباره شارژ نمی‌کند.

### سرعت ربات در گروه‌های شلوغ

- کوئری‌های دیتابیس ربات در یک thread pool اجرا می‌شوند (`BOT_DB_THREADS`، پیش‌فرض ۸)، نه پشت سر هم در یک thread؛
  پس کار یک گروه پشت گروه‌های دیگر معطل نمی‌ماند. درستی موجودی‌ها با تراکنش و قفل ردیف تضمین می‌شود و
  موقع پرداخت جایزه همه‌ی کاربرهای مسابقه به ترتیب شناسه قفل می‌شوند تا بن‌بست پیش نیاید.
- اتصال دیتابیس تا `DB_CONN_MAX_AGE` ثانیه (پیش‌فرض ۶۰) دوباره استفاده می‌شود، نه یک اتصال تازه برای هر کوئری.
- دکمه‌هایی که فقط صفحه را عوض می‌کنند (رتبه‌بندی، قوانین، منوی پیوی) چرخک‌شان را همان اول می‌بندند.
- لینک مسابقه‌ی آرکید در گروه، فایل‌های همان بازی را از اول صفحه preload می‌کند (موازی با درخواست `/info`).
- صفحه‌ی بازی‌های زنده (شطرنج، پوکر، دوز) تقریباً هر ثانیه می‌پرسد «چیزی عوض شده؟». نسخه‌ی هر وضعیت چند ثانیه در
  Redis می‌ماند (`arcade/board.py`: `publish_version`) و جواب «تغییری نیست» بدون خواندن مسابقه از Postgres داده
  می‌شود؛ هر حرکت یا لغو همان لحظه آن را عوض می‌کند، پس هیچ حرکتی دیر دیده نمی‌شود.
- رندر «مارپیچ سقوط» ضخامت سکوها را با مسیرهای دقیق می‌کشد (به‌جای شش نسخه‌ی جابه‌جای هر طبقه): حدود ۲٫۵ برابر سریع‌تر.
- **روانی بازی‌های آرکید روی گوشی‌های ضعیف:** پس‌زمینه‌ی هر بازی روی یک بوم جدا (`#stage-back`) فقط وقتی عوض شود دوباره
  کشیده می‌شود، نه هر فریم (`env.backdrop`)؛ کیفیت هر بازی با سهم فریم‌های کند (بالای ۲۵ و ۴۰ میلی‌ثانیه) زود پایین می‌آید
  و برای همان بازی در گوشی کاربر به خاطر سپرده می‌شود؛ پس‌زمینه‌ی صفحه‌ها ثابت است و `backdrop-filter` ندارد.
- **میز پوکر:** حلقه‌ی زمان نوبت با یک transition خطی CSS خالی می‌شود (نه رنگ کردن هر فریم)، برگه‌ها blur ندارند و
  گفت‌وگوی میز همراه همان پرسش «چیزی عوض شده؟» می‌آید (`chat_after`)، پس درخواست جدایی ندارد.

### تنظیمات بازی‌ها و تعداد شرکت‌کننده

صفحه‌ی **«تنظیمات بازی‌ها»** (`/admin/games/gamesetting/`) برای هر بازی یک ردیف دارد:

- **حداقل و حداکثر شرکت‌کننده** با دکمه‌های `−` و `+` کم و زیاد می‌شود و همان لحظه ذخیره می‌شود.
  «حداقل» یعنی اگر تا پایان عضوگیری این تعداد نیایند مسابقه لغو و ورودی‌ها برمی‌گردد؛ «حداکثر» ظرفیت لابی است
  (با پر شدن ظرفیت، مسابقه بدون انتظار شروع می‌شود).
- **کلید فعال/غیرفعال:** بازی غیرفعال از منوی `/game`، تنظیمات گروه‌ها و تمرین آزاد آرکید حذف می‌شود.
- اکشن‌های گروهی: «۱ نفر/۵ نفر بیشتر یا کمتر»، «برگرداندن به پیش‌فرض»، «فعال/غیرفعال کردن».

هر بازی یک **بازه‌ی مجاز** دارد که از آن بیرون نمی‌رود: شطرنج و دوز همیشه ۲ نفر، بازی‌های شانسی حداکثر ۱۲،
زنجیره‌ی کلمات حداکثر ۲۰ و بقیه (از جمله آرکید) تا ۵۰ نفر. پیش‌فرض‌ها همان مقدارهای داخل کد هر بازی‌اند.
تغییرها روی مسابقه‌های **بعدی** اعمال می‌شوند (حداکثر ۱۵ ثانیه بعد در ربات)؛ مسابقه‌ای که از قبل ساخته شده با همان
تنظیمات خودش تمام می‌شود.

قالب CSV (ردیف اول عنوان ستون‌ها، UTF-8):

| مدل | ستون‌ها |
|---|---|
| کلمات | `word,category` |
| سوال‌ها | `category,text,option1,option2,option3,option4,correct,difficulty` (`correct` از ۱ تا ۴؛ دسته: `general` `freefire` `football` `movie` `science`) |
| پازل ایموجی | `emojis,answer,alt_answers` (جایگزین‌ها با `|`) |
| جمله‌های تایپ | `text` |

موجودی سکه از پنل قابل ویرایش نیست؛ اعطای سکه فقط با `/grant` (ثبت در ledger با نوع `ADMIN_GRANT`).

## اضافه کردن بازی جدید

### بازی متنی — فقط یک فایل

`games/plugins/my_game.py`:

```python
from games.engine.registry import register_game
from games.engine.rounds import RoundGame


@register_game
class MyGame(RoundGame):
    key = "my_game"
    title_fa = "بازی من"
    emoji = "🎲"
    description_fa = "توضیح یک‌خطی"
    rounds = 5
    round_seconds = 20

    async def begin_round(self):
        self.answer = "سلام"
        await self.ctx.send(f"{self.header()}\n\nبنویس: سلام")

    async def on_message(self, msg):
        if self.round_open and msg.text.strip() == self.answer:
            self.add_score(msg.player.user_id, 10)
            await self.ctx.send(f"✅ {msg.player.mention}")
            await self.close_round()

    async def on_round_timeout(self):
        await self.ctx.send("⏰ وقت تمام شد")
```

فایل‌های `games/plugins` خودکار بارگذاری می‌شوند و بازی در منوی `/game` و تنظیمات گروه ظاهر می‌شود.
پلاگین فقط با `self.ctx` کار می‌کند (`send`، `edit`، `send_photo`، `send_dice`، `flash`، `set_timer`، `content`، `end_game`)،
پس بدون تلگرام و با `tests/fakes.py` تست می‌شود. برای بازی غیرراندی از `BaseGame` ارث ببرید (مثل `word_chain.py`).

### بازی آرکید — دو فایل منطق (+ یک فایل رندر)

1. `arcade/static/arcade/<key>/core.js` — منطق قطعی: `newState(seed, config)`، `applyInput(state, [t_ms, ...])`، `step(state)`
   و فیلدهای `state.over`، `state.score`، `state.level`. فقط عدد صحیح، بدون `Math.random` و بدون وابستگی به فریم‌ریت.
2. `arcade/sim/<key>.py` — همان منطق، خط‌به‌خط، با `@register_simulator` و یک `demo_policy` (بازیکن خودکار برای تست).
3. `arcade/static/arcade/<key>/render.js` — رندر و افکت‌ها (هیچ منطق بازی این‌جا نباشد). قاعده‌های سرعت:
   پس‌زمینه‌ی ثابت با `env.scene(...)` و هر جزء پرجزئیات با `env.sprite(key, w, h, paint)` فقط **یک بار** کشیده
   می‌شود و در هر فریم فقط `drawImage` می‌ماند؛ متریال‌ها (چوب، فلز، چمن، کره‌ی سایه‌خورده، سایه‌ی نرم) در
   `common/art.js` هستند. در `draw` از `shadowBlur` و گرادیان تمام‌صفحه استفاده نکنید (روی گوشی فریم می‌اندازد).
4. ساخت fixture و تست تطابق:

```bash
python manage.py arcade_fixtures <key>
node arcade/jstests/parity.js <key>
pytest tests/test_arcade_parity.py
```

بازی خودکار در منوی «آرکید»، `/arcade` و تنظیمات گروه ظاهر می‌شود.

## تصمیم‌های طراحی

جاهایی که صورت مسئله مبهم بود و انتخابی انجام شد:

- **رابط پلاگین:** `on_message` و `on_callback` به‌جای `Update` خام تلگرام یک رویداد ساده (`IncomingMessage` / `IncomingCallback`) می‌گیرند تا منطق بازی‌ها بدون تلگرام تست شود.
- **تقسیم جایزه با بازیکن کم:** سهم‌های اضافه به نسبت بین رتبه‌های موجود پخش می‌شود (۶۰-۳۰-۱۰ با دو نفر ⇒ ۶۰:۳۰). گرد کردن رو به پایین و باقیمانده به نفر اول؛ جمع پرداختی همیشه دقیقاً برابر pot است.
- **تساوی:** امتیاز برابر ⇒ کسی که زودتر به آن رسیده جلوتر است؛ اگر زمان هم برابر بود سهم آن رتبه‌ها مساوی تقسیم می‌شود. تساوی صفر-صفر (مثلاً کسی بازی نکرده) pot را مساوی برمی‌گرداند ولی «برد» حساب نمی‌شود تا نشود با مسابقه‌های خالی آمار برد و جایزه‌ی دستاورد جمع کرد.
- **سازنده‌ی مسابقه** خودکار عضو لابی می‌شود (اگر سکه‌اش برسد). با پر شدن ظرفیت، لابی زودتر بسته می‌شود.
- **بازی‌های دونفره** (دوز) مرحله‌ی انتخاب تقسیم ندارند: برنده همه را می‌برد و مساوی نصف-نصف.
- **سکه‌ی نجات** با `/daily` داده می‌شود وقتی جایزه‌ی آن روز گرفته شده و موجودی صفر است؛ نوع تراکنش `RESCUE` به فهرست انواع اضافه شده.
- **دعوت دوست:** فقط برای کاربری که اولین `/start` او با لینک دعوت بوده؛ جایزه وقتی که دعوت‌شده حداقل یک بازی تمام کرده **و** حسابش ۲۴ ساعته شده باشد (در پایان بازی یا هنگام `/daily` بررسی می‌شود).
- **جدول هفتگی** از روی تاریخ محاسبه می‌شود (ساعت تهران، شروع هفته شنبه)، پس «ریست» خودکار است؛ job شنبه‌ها فقط قهرمان هفته‌ی قبل را در گروه‌ها اعلام می‌کند (و یک بار هم بعد از بالا آمدن ربات، برای جبران خاموشی).
- **بازی‌های دایس** یک پلاگین با پنج حالت‌اند. 🎲🎯🎳 امتیاز برابر مقدار دایس؛ 🏀 مقدار ۴ و ۵ و ⚽ مقدار ۳ تا ۵ یک امتیاز (گل). بعد از پایان مهلت نوبت، ربات خودش به نام بازیکن پرتاب می‌کند.
- **حدس عدد:** راهنمای بزرگ‌تر/کوچک‌تر روی یک پیام ثابت به‌روز می‌شود (نه یک پیام برای هر حدس) تا به حد ۲۰ پیام در دقیقه‌ی تلگرام برای گروه نخوریم. همه‌ی ویرایش‌ها از صف ویرایش (`bot/tg.py`) رد می‌شوند و `AIORateLimiter` هم فعال است.
- **موتور گرافیک:** Canvas خالص به‌جای Phaser (سبک‌تر، بدون وابستگی و asset خارجی). فونت Vazirmatn از CDN با جایگزین سیستم.
  همه‌ی تصویرها رویه‌ای (procedural) ساخته می‌شوند و در اسپرایت‌های کش‌شده می‌مانند؛ هیچ فایل تصویر یا asset
  بیرونی در پروژه نیست.
- **کیفیت تطبیقی:** اگر میانگین فریم در دو بازه‌ی پیاپی از حدود ۴۳ فریم در ثانیه کمتر شود، اول وضوح بوم
  (از ۲× به ۱٫۵× و بعد ۱×) و تعداد ذره‌ها کم می‌شود. این انتخاب فقط ۲۴ ساعت به خاطر سپرده می‌شود تا کندی موقتی
  (مثلاً حالت صرفه‌جویی باتری) کیفیت را برای همیشه پایین نگه ندارد.
- **تعداد شرکت‌کننده:** از پنل ادمین برای هر بازی قابل‌تنظیم است ولی از بازه‌ی مجاز همان بازی بیرون نمی‌رود
  (بازی‌های دونفره قفل‌اند). ربات تنظیمات را در حافظه نگه می‌دارد و هر ۱۵ ثانیه و همچنین درست قبل از ساخت هر
  مسابقه از دیتابیس تازه می‌کند. با ظرفیت‌های بزرگ، فهرست بازیکن‌ها در پیام لابی/جدول/نتیجه کوتاه می‌شود
  («… و N نفر دیگر») تا از سقف ۴۰۹۶ نویسه‌ی پیام تلگرام رد نشود.
- **آرکید:** seed مسابقه برای همه‌ی تلاش‌ها یکی است؛ تلاش ردشده هم از سهمیه کم می‌شود؛ خروج از صفحه یعنی پایان همان تلاش (جلوی توقف برای وقت‌کشی)؛ کلاینت ۳ ثانیه مانده به پایان مسابقه تلاش را می‌بندد تا ثبت شود. اگر همه‌ی بازیکن‌ها تلاش‌هایشان را تمام کنند مسابقه زودتر تمام می‌شود.
- **فلگ در برابر رد:** لاگ خراب، «سریع‌تر از زمان واقعی» و تپ‌های غیرانسانیِ زیاد **رد** می‌شوند؛ اختلاف امتیاز ادعایی با محاسبه‌ی سرور، چند تپ خیلی سریع، یا بازی آهسته‌شده فقط **فلگ** می‌شوند (امتیاز محاسبه‌ی سرور معتبر است).
- **مرحله‌های «سیخ‌زن»:** الگوهای رفت‌وبرگشتی نامتقارن‌اند تا همه‌ی محیط دایره در دسترس باشد؛ تست `test_every_handmade_and_procedural_level_is_solvable` حل‌پذیری هر مرحله را بررسی می‌کند.
- **اکشن لغو در پنل ادمین** مستقیم در دیتابیس اجرا می‌شود و ربات حداکثر ۱۵ ثانیه بعد اجرای زنده‌ی همان مسابقه را متوقف و در گروه اعلام می‌کند.
- **شطرنج:** موتور قوانین را خودمان نوشته‌ایم (`games/chess/engine.py`، بدون وابستگی خارجی) و با اعداد مرجع perft تست شده؛ حرکت‌ها با نماد جبری استاندارد (SAN) ثبت می‌شوند. صفحه‌ی تصویری گروه همیشه از دید سفید است.
- **ساعت شطرنج (مثل مسابقات فیده):** هر بازیکن ساعت خودش را دارد و بعد از هر حرکت افزایش «فیشر» کنترل زمانی به آن اضافه می‌شود (`games/chess/live.py`: `TIME_CONTROLS`؛ حریف تصادفی ۵+۳). کلاسیک فیده (۹۰ دقیقه تا حرکت ۴۰، بعد ۳۰ دقیقه‌ی اضافه، با ۳۰ ثانیه افزایش از حرکت اول) با `MOVE_BONUS` پیاده شده و در مینی‌اپ لحظه‌ی اضافه شدن آن ۳۰ دقیقه پیام کوتاهی نشان داده می‌شود. مثل سایت‌های شطرنج، اولین حرکت هر طرف از ساعت کم نمی‌شود و فقط ۶۰ ثانیه مهلت جدا دارد. تمام شدن ساعت یعنی باخت، مگر حریف فقط شاه داشته باشد که مساوی است (قانون ۶.۹). وضعیت‌های ذخیره‌شده‌ی قدیمی موقع خواندن به قالب تازه درمی‌آیند.
- **تصویرهایی که ربات می‌فرستد:** صفحه‌ی شطرنج (چوبی، با مهره‌های استانتون حجم‌دار) و برگه‌ی مسابقه‌ی تایپ کاملاً با Pillow و رویه‌ای کشیده می‌شوند؛ مهره‌ها به فونت نمادها وابسته نیستند (`games/chess/pieces.py`). صفحه‌ی شطرنج JPEG است تا هر حرکت سریع بارگذاری شود.
- **کارت نتیجه:** در پایان هر مسابقه (متنی یا آرکید) ربات یک کارت تصویری می‌فرستد: سکوی سه‌نفره با مدال، نام، امتیاز و جایزه‌ی هر نفر (`bot/cards.py`)، و متن کامل نتیجه کپشن همان عکس است. اگر متن از سقف کپشن تلگرام بلندتر باشد کارت جدا و متن زیر آن می‌آید؛ اگر ساخت یا ارسال تصویر نشد (مثلاً فونت روی سرور نبود) فقط همان متن فرستاده می‌شود. ایموجی و نویسه‌هایی که فونت ندارد از نام‌ها حذف می‌شوند.
- **دکمه‌های رنگی:** دکمه‌های اینلاین با فیلد `style` تلگرام (Bot API 9.4: `primary` آبی، `success` سبز، `danger` قرمز) رنگ می‌گیرند: «شرکت» سبز و «لغو» قرمز، گزینه‌های منو آبی، پیش‌فرض‌ها سبز، در دوز ❌ قرمز و ⭕️ آبی، و در شطرنج مهره‌ی انتخاب‌شده آبی، خانه‌های مقصد سبز و خانه‌ی زدن قرمز. همه از `bot/ui.py` ساخته می‌شوند؛ چون python-telegram-bot 21 این فیلد را نمی‌شناسد از راه `api_kwargs` فرستاده می‌شود. کلاینت‌های قدیمی دکمه را ساده نشان می‌دهند و با `BUTTON_STYLES=False` رنگ‌ها کاملاً خاموش می‌شوند. پلاگین‌های بازی به‌جای `(متن، داده)` می‌توانند `Button(متن، داده، رنگ)` برگردانند.
- **قوانین هر بازی:** هر بازی (متنی و آرکید) سه خط قانون کوتاه در `rules_fa` دارد. در بازی‌های متنی عددها از ثابت‌های همان کلاس پر می‌شوند (`{points}`، `{rounds}`، …) تا با تغییر کد، متن قوانین غلط نشود. قوانین سه جا دیده می‌شود: `/rules` (فهرست بازی‌ها و قوانین کامل هر کدام)، دکمه‌ی «📖 قوانین بازی» زیر لابی و جدول آرکید (پنجره‌ی هشدار فقط برای همان کاربر، حداکثر ۲۰۰ نویسه) و صفحه‌ی شروع مینی‌اپ (کنترل، امتیاز، پایان بازی).
- **لحن متن‌ها:** همه‌ی متن‌های ربات و مینی‌اپ خطاب دوستانه‌ی «تو» با فعل نوشتاری دارند («می‌شود»، نه «می‌شه»)؛ تست `test_texts_use_one_written_tone` جلوی برگشتن شکل محاوره‌ای را می‌گیرد. تاریخ تراکنش‌ها شمسی است («۱۹ مهر ۱۴:۳۰»).
- **پردازش هم‌زمان:** به‌روزرسانی‌های چت‌های مختلف هم‌زمان پردازش می‌شوند (`bot/concurrency.py`) تا مکث یا کندی تلگرام برای یک گروه بقیه‌ی گروه‌ها را معطل نکند؛ پیام‌های هر چت به همان ترتیب رسیدن پردازش می‌شوند، پس «اولین جواب درست» تغییری نمی‌کند. کلیک دکمه‌ها در گروه به ترتیبِ *همان پیام* (لابی، صفحه‌ی بازی یا منو) است، نه کل گروه؛ پس ده بازی هم‌زمان در یک گروه پشت هم صف نمی‌کشند و وضعیت هر بازی با قفل خودش (`ActiveMatch.lock`) و پول با قفل ردیف دیتابیس محافظت می‌شود. نوبتِ چت قبل از سهمیه‌ی هم‌زمانی گرفته می‌شود، پس یک گروه شلوغ حداکثر یک جای پردازش را می‌گیرد و پیوی‌ها و گروه‌های دیگر معطلش نمی‌شوند. تعداد با `BOT_CONCURRENT_UPDATES` تنظیم می‌شود.
- **نام‌های بلند:** نام بازیکن‌ها در پیام‌های بازی حداکثر ۲۴ نویسه است و فهرست نام‌ها در پیام شروع بریده می‌شود تا هیچ پیامی از سقف طول تلگرام رد نشود.
- **شطرنج گرافیکی (مینی‌اپ):** وقتی مینی‌اپ راه‌اندازی شده باشد، شطرنج در یک صفحه‌ی واقعی داخل تلگرام بازی می‌شود (`arcade/board/chess.js`): کشیدن مهره یا دو لمس با حرکت نرم مهره‌ها، ساعت تیک‌تاک‌کنان با دهم ثانیه و هشدار وقت کم، فهرست حرکت‌ها با شکل مهره‌ها، صدای حرکت/زدن/کیش (`arcade/common/sfx.js`، بدون فایل صوتی)، پنج رنگ‌بندی تخته (چوب گردو با رگه‌ی واقعی، سبز مسابقه، سنگ مرمر، آبی، بنفش؛ فقط CSS)، چرخاندن صفحه، خانه‌های مجاز، انتخاب مهره‌ی ارتقا، مهره‌های گرفته‌شده، تسلیم و پیشنهاد مساوی. مثل اپ‌های شطرنج **پیش‌حرکت** (premove) هم دارد: وقتی نوبت حریف
است حرکت بعدی را می‌کشی (فلش قرمز) و به محض رسیدن نوبت، اگر هنوز قانونی باشد، فرستاده می‌شود. با دکمه‌های پایین، فلش‌های
کیبورد یا لمس فهرست حرکت‌ها می‌شود وضعیت‌های قبلی را **مرور** کرد؛ سطح و نشان فروشگاه هر بازیکن کنار نامش است. حرکت‌ها فقط در سرور و با موتور قوانین اعتبارسنجی می‌شوند (`games/chess/live.py`، وضعیت در `Match.state["board"]`). ربات هر ۲ ثانیه وضعیت را می‌خواند، عکس صفحه را در گروه برای تماشاچی‌ها به‌روز می‌کند، پایان مهلت را اعمال و نتیجه را اعلام می‌کند؛ بعد از ری‌استارت هم بازی ادامه پیدا می‌کند. بدون مینی‌اپ، همان نسخه‌ی داخل گفت‌وگو (عکس + کیبورد) اجرا می‌شود.
- **دوز و دوز چهارتایی گرافیکی (مینی‌اپ):** همین سازوکار برای دوز ۳×۳ و دوز چهارتایی ۷×۶ هم هست (`games/gridlive.py`، `arcade/board/grid.js`): مهره همان لحظه‌ی لمس از بالای ستون تا جای خودش می‌افتد، جای افتادن کم‌رنگ نشان داده می‌شود، خط برنده، ساعت هر حرکت، صدا و تسلیم؛ ربات صفحه را با ایموجی در گروه نشان می‌دهد. بدون مینی‌اپ نسخه‌ی دکمه‌ای داخل گفت‌وگو اجرا می‌شود.
- **میز پوکر گرافیکی (مینی‌اپ):** صندلی‌ها دور میز بیضی (`arcade/board/poker.js`)، کارت‌های واقعی، ژتون شرط جلوی هر نفر که به پات می‌رود، دکمه‌ی دیلر، حلقه‌ی زمان نوبت، رو شدن کارت‌ها با هایلایت ۵ کارت برنده، قدرت دست خودت («دو جفت آس و بی‌بی»)، دکمه‌های نصف/سه‌چهارم/کل پات و رتبه‌بندی پایانی. مثل اپ‌های پوکر وقتی نوبت دیگری است **حرکت از پیش** (چک/فولد، چک،
کال همین مبلغ، کال هر مبلغ) انتخاب می‌شود و با رسیدن نوبت خودکار انجام می‌شود (اگر شرط عوض شود لغو می‌شود). در آل‌این
اول کارت‌ها رو می‌شوند و بعد فلاپ، ترن و ریور یکی‌یکی می‌آیند (سرور وقفه‌ی بعد از دست را به همان اندازه بلند می‌کند).
پات‌های جانبی، نام دست هر نفر در شودان، برگه‌ی **تاریخچه‌ی دست** (همین دست و نتیجه‌ی دست قبل) و **جدول رتبه‌ی دست‌ها** هم هست.
- **هشدار ادمین نبودن ربات:** اگر Privacy Mode ربات روشن باشد و ربات ادمین گروه نباشد، پیام‌ها را نمی‌بیند و بازی‌های تایپی کار نمی‌کنند؛ در این حالت منوی `/game` همین را با هشدار می‌گوید.
- **قانون جایزه:** فقط بازیکن‌هایی که امتیاز گرفته‌اند از جایزه‌ی کل سهم می‌برند (امتیاز صفر یعنی باخت). اگر امتیازگیرها کمتر از سهم‌های تقسیم باشند، سهم‌ها به همان نسبت بین آن‌ها پخش می‌شود؛ اگر هیچ‌کس امتیاز نگیرد یا بازی دونفره مساوی شود، جایزه‌ی کل مساوی بین همه تقسیم می‌شود. هم‌رتبه‌ها (امتیاز و زمان برابر) سهم جایگاه‌هایشان را نصف می‌کنند و جمع پرداختی همیشه برابر جایزه‌ی کل است.
- **راهنمای کامل:** `/rules` بخش‌های «ساخت و شرکت»، «امتیاز و جایزه» و «انواع بازی» دارد و عددهایش (زمان عضوگیری، XP، تعداد تلاش آرکید، تعداد راند و مهلت هر بازی) مستقیم از تنظیمات و کلاس‌های بازی خوانده می‌شود. لابی هم نوع بازی را نشان می‌دهد (مثلاً «راندی: ۷ راند، هر راند حداکثر ۲۵ ثانیه»).
- **سرعت بارگذاری مینی‌اپ:** فونت Vazirmatn از خود سرور سرو می‌شود (`/arcade/font/…`، از بسته‌ی fonts-vazirmatn داخل Docker) و دیگر به CDN خارجی وابسته نیست؛ `core.js` و `render.js` هر بازی موازی دانلود می‌شوند و فایل‌های `/static/arcade/` (که همه با `?v=` نسخه‌دارند) یک سال کش می‌شوند.
- **شطرنج با کامپیوتر:** اولین کاشی منوی تمرین مینی‌اپ (`/arcade/chess/`) است: سه سطح آسان، متوسط و سخت (جست‌وجوی آلفا-بتا در `games/chess/ai.py`)، رنگ مهره‌ها تصادفی، بدون سکه و بدون ساعت،
با دکمه‌ی **راهنما** (فلش سبز حرکت پیشنهادی) و **برگشت حرکت** (حرکت خودت و جواب کامپیوتر؛ بعد از مات هم، ولی نه بعد از تسلیم). حرکت‌ها در سرور با همان موتور قوانین بررسی می‌شوند و بازی نیمه‌کاره با باز کردن دوباره‌ی صفحه ادامه پیدا می‌کند.
- **پشتیبان خودکار:** ربات هر `BACKUP_INTERVAL_MINUTES` دقیقه (پیش‌فرض ۳۰؛ ۰ = خاموش) از کل دیتابیس یک فایل `backup-تاریخ.json.gz` می‌سازد و در پیوی سوپرادمین‌ها (یا `BACKUP_CHAT_IDS`) می‌فرستد؛ `/backup` همین حالا یکی می‌فرستد. برگرداندن روی دیتابیس خالی: `python manage.py migrate` و بعد `python manage.py loaddata backup-....json.gz`. فایل اطلاعات کاربران را دارد؛ آن را جای امن نگه دارید. بالای ۵۰ مگابایت تلگرام فایل را نمی‌فرستد و به‌جایش هشدار می‌آید.
- **نام واحد امتیاز:** با `COIN_NAME` و `COIN_EMOJI` در `.env` (مثلاً «اعتبار» و 💎) همه‌ی متن‌ها عوض می‌شوند؛ فقط ظاهر است و واحد همچنان امتیاز مجازی است.
- **شارژ اعتبار از پنل:** در لیست کاربران پنل ادمین، اکشن «شارژ اعتبار مجازی» به کاربرهای انتخاب‌شده هر مقدار اعتبار مجازی می‌دهد (از مسیر ledger، با نوع «هدیه‌ی ادمین»).
- **جایزه‌ی ویژه:** ادمین گروه با `/prize <متن>` جایزه‌ای را که خودش بیرون از ربات به نفر اول می‌دهد اعلام می‌کند (`/prize -` پاک می‌کند)؛ در لابی و نتیجه نشان داده می‌شود. ربات هیچ پولی جابه‌جا نمی‌کند.
- **خرید آیتم ظاهری با استار تلگرام:** اگر برای آیتم فروشگاه «قیمت به استار» گذاشته شود، کنار خرید با سکه دکمه‌ی پرداخت با Telegram Stars (ارز `XTR`، پرداخت رسمی تلگرام) هم می‌آید. خرید فقط آیتم ظاهری می‌دهد، هیچ‌وقت سکه/اعتبار نمی‌دهد، و رسیدش در «خریدهای استار» پنل ثبت می‌شود.
- **نمادهای بازی‌ها:** منو و صفحه‌ی شروع مینی‌اپ به‌جای ایموجی یک نماد تصویری برای هر بازی دارند که با همان جعبه‌ابزار گرافیکی کشیده می‌شود (`common/icons.js`).
- **ظاهر پیام‌ها:** پیام‌های ربات با تیتر، خط جداکننده، نقل‌قول (`blockquote`) و نوار پیشرفت متنی قالب‌بندی شده‌اند؛ همه در `core/texts.py`.
- **کش فایل‌های بازی:** آدرس `core.js` و `render.js` هر بازی یک پارامتر نسخه (`?v=`) دارد تا بعد از به‌روزرسانی، تلگرام نسخه‌ی قدیمی را نشان ندهد.
- **تنظیمات گروه:** مقادیر ورودی و زمان با هر کلیک بین گزینه‌های ثابت می‌چرخند؛ حداقل یک بازی باید فعال بماند.

## چه چیزهایی تست شده و چه چیزهایی نه

تست‌شده (`pytest`، روی PostgreSQL 16):

- wallet: همزمانی (چند کسر همزمان، موجودی منفی نمی‌شود)، idempotency، تطابق ledger، تغییرناپذیری ledger
- حسابرسی کامل سکه: یک دور از همه‌ی مسیرهای پولی (شارژ، فروش، انتقال، ورودی/جایزه/لغو مسابقه، فروشگاه، کلیک‌های تکراری) بدون مغایرت، و پیدا شدن جایزه‌ی اضافه یا رسید نیمه‌تسویه
- نقش‌ها و دسترسی مدیران: هر بخش و دستور پنل فقط برای دسترسی خودش، افزودن/ویرایش/حذف مدیر فقط برای مالک، دادن سکه با تأیید یک‌بارمصرف
- جوین اجباری و API ربات‌های دیگر: منتظر ماندن /start و ادامه‌ی دعوت و شرکت در مسابقه بعد از عضویت، مستثنا بودن مدیران، گیر نیفتادن کاربر وقتی ربات ادمین کانال نیست، رویدادهای کانال و بلاک، پنل کانال‌ها و کلیدها، احراز هویت و سقف API، کش عضویت، صفحه‌ی عضویت مینی‌اپ و امضا و تکرار وب‌هوک‌ها
- شطرنج و پوکر زنده: برگشت حرکت و راهنمای تمرین، باز شدن مرحله‌ای کارت‌ها در آل‌این و وقفه‌ی بلندترش، پات‌های جانبی، و این‌که جواب سریع «تغییری نیست» هیچ حرکت یا لغوی را پنهان نمی‌کند
- تقسیم جایزه: همه‌ی splitها، بازیکن کمتر از سهم‌ها، تساوی، گرد کردن (جمع = pot)
- لابی، عضویت، لغو و refund، بازیابی بعد از ری‌استارت
- نرمال‌سازی فارسی؛ منطق هر ۱۰ بازی متنی بدون تلگرام
- شبیه‌ساز هر ۱۴ بازی آرکید در برابر fixtureها؛ API مینی‌اپ (HMAC، session، ضدتقلب، rate limit)
- handlerهای ربات با Update ساختگی؛ پنل ادمین، رتبه‌بندی، قهرمان هفته، فروشگاه
- تنظیمات بازی‌ها: دکمه‌های کم/زیاد، بازه‌ی مجاز هر بازی، فعال/غیرفعال، اثر روی ظرفیت لابی و ساخت مسابقه در ربات
- دکمه‌های رنگی (فیلد `style` در JSON کیبورد)، قوانین هر بازی و سقف ۲۰۰ نویسه‌ی پنجره‌ی هشدار، منوی پیوی، یک‌دستی لحن متن‌ها، تاریخ شمسی، حفظ ترتیب در پردازش هم‌زمان، و این‌که یک گروه شلوغ جای پردازش پیوی‌ها و گروه‌های دیگر را نمی‌گیرد
- **همه‌ی دکمه‌ها** (`tests/test_buttons.py`): یک خزنده از منوی پیوی، منوی گروه، پنل مدیریت و داخل هر بازی، تک‌تک دکمه‌های اینلاین را از همان جدول handlerهای ربات واقعی می‌زند (حدود ۶۰۰ کلیک) و هر دکمه‌ای که handler نداشته باشد، خطا بدهد یا بی‌جواب بماند را گزارش می‌کند
- **فشار هم‌زمان** (`tests/test_stress.py`): چند لابی در یک گروه، دوبار زدن «شرکت»، انتقال، فروش و تصمیم هم‌زمان چند مدیر روی همان رسید، و بعد تسویه‌ی دوباره و هم‌زمان همه‌ی مسابقه‌ها؛ حسابرسی کامل ledger باید تمیز بماند، هیچ موجودی منفی نشود و ظرفیت لابی رعایت شود. ۲۱ کلیک هم‌زمان «شرکت» روی یک لابی ۱۰نفره هم دقیقاً ۱۰ نفر را وارد می‌کند
- پیام دعوت گروه‌ها (زمان‌بندی، جایگزینی پیام قبلی، رد کردن گروه مشغول و گروه بیرون‌کرده، خاموش کردن از `/settings` و پنل) و انتشار پست‌های کانال؛ رسید واریز فروش به‌صورت عکس یا فایل PDF

بررسی‌شده در مرورگر (نه در `pytest`): هر ۱۴ بازی آرکید یک دور کامل اجرا شدند (شروع ← ورودی تصادفی ← ثبت امتیاز)
بدون خطای جاوااسکریپت، و زمان کشیدن هر فریم قبل و بعد از بازنویسی گرافیک اندازه گرفته شد. صفحه‌های شطرنج و پوکر با دو
بازیکن هم‌زمان در دو صفحه بازی شدند (پیش‌حرکت شطرنج، مرور حرکت‌ها، حرکت از پیش پوکر، آل‌این تا شودان) و همه‌ی صفحه‌ها در
عرض ۳۶۰ و ۳۹۰ پیکسل بدون اسکرول افقی بررسی شدند. تطابق JS/Python هم با `node arcade/jstests/parity.js` (۸۴ از ۸۴) تأیید شد.

**تست‌نشده در محیط ساخت این پروژه** (قبل از استفاده‌ی واقعی خودتان بررسی کنید):

- اتصال واقعی به تلگرام (توکن ربات در دسترس نبود): رفتار ربات با تلگرام ساختگی تست شده، نه با API واقعی.
- `docker compose up` (Docker روی ماشین ساخت نصب نبود).
- حس بازی (سختی، سرعت، کنترل لمسی) روی گوشی واقعی: منطق و رندر بررسی شده ولی اعداد سختی احتمالاً نیاز به تنظیم دارند.
- نرخ فریم روی گوشی واقعی: سرعت رندر فقط روی مرورگر دسکتاپ (با بوم هم‌اندازه‌ی گوشی) اندازه‌گیری شده است.
