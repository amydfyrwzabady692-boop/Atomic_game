# ربات بازی‌های گروهی تلگرام با سکه‌ی مجازی

رباتی که به گروه‌های تلگرام اضافه می‌شود و مسابقه‌های گروهی امتیازی برگزار می‌کند:
۱۱ بازی داخل خود گروه (از جمله شطرنج تصویری) و ۱۴ بازی آرکید به‌صورت Telegram Mini App.
بازیکن‌ها با **سکه‌ی مجازی داخل ربات** وارد مسابقه می‌شوند و برنده‌ها سکه می‌برند.

> **قانون غیرقابل‌تغییر:** سکه فقط امتیاز مجازی و تفریحی است. در هیچ جای این پروژه خرید سکه با
> پول واقعی، تبدیل سکه به پول، برداشت، انتقال سکه بین کاربران یا دریافت اطلاعات بانکی وجود ندارد
> و نباید اضافه شود. (تست `test_no_real_money_or_transfer_paths_exist` همین را بررسی می‌کند.)

استک: Python 3.12 · Django 5 · PostgreSQL 16 · Redis · python-telegram-bot 21 (async) · Docker

## راه‌اندازی سریع با Docker

```bash
cp .env.example .env        # مقادیر را پر کنید (حداقل BOT_TOKEN و SUPERADMIN_IDS)
docker compose up -d --build
docker compose exec web python manage.py seed_content      # کلمات، سوال‌ها، پازل‌ها، فروشگاه
docker compose exec web python manage.py createsuperuser   # ورود به پنل ادمین
```

سرویس‌ها:

| سرویس | کار |
|---|---|
| `db` | PostgreSQL 16 |
| `redis` | وضعیت زنده، قفل‌ها و rate limit |
| `web` | پنل ادمین جنگو (`/admin/`) + صفحه و API مینی‌اپ (`/arcade/`) روی پورت ۸۰۰۰ |
| `bot` | ربات تلگرام (`python manage.py runbot`) |

سرویس `web` هنگام بالا آمدن `migrate` را اجرا می‌کند و `bot` بعد از سالم شدن آن شروع می‌شود.

## ساخت ربات در BotFather

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید و با `/newbot` ربات بسازید؛ توکن را در `BOT_TOKEN` بگذارید.
2. **Privacy Mode را خاموش کنید** تا ربات جواب بازیکن‌ها را در گروه ببیند:
   `/setprivacy` ← انتخاب ربات ← **Disable**.
   (اگر ربات قبلاً عضو گروهی بوده، یک بار حذف و دوباره اضافه‌اش کنید. ادمین کردن ربات در گروه هم همین اثر را دارد.)
3. `/setjoingroups` ← **Enable** تا بشود ربات را به گروه اضافه کرد.
4. آیدی عددی خودتان را (مثلاً از @userinfobot) در `SUPERADMIN_IDS` بگذارید.
5. برای بازی‌های آرکید، مینی‌اپ را هم ثبت کنید ([پایین‌تر](#مینیاپ-آرکید-https-و-دامنه)).

بعد ربات را به گروه اضافه کنید. هر بازیکن باید **یک بار در پیوی ربات `/start` بزند** (دکمه‌اش زیر پیام لابی هست).

## تنظیم `.env`

| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن ربات |
| `BOT_USERNAME` | یوزرنیم ربات بدون `@` (اختیاری؛ از تلگرام خوانده می‌شود) |
| `SUPERADMIN_IDS` | آیدی عددی سوپرادمین‌ها با ویرگول |
| `DATABASE_URL` | مثل `postgres://user:pass@db:5432/gamebot` |
| `REDIS_URL` | مثل `redis://redis:6379/0` (اگر خالی باشد fakeredis درون‌حافظه‌ای، **فقط توسعه**) |
| `WEBHOOK_URL` | خالی = polling. برای production آدرس عمومی HTTPS (ربات روی `WEBHOOK_PORT` گوش می‌دهد) |
| `WEBHOOK_SECRET` | رشته‌ی تصادفی برای مسیر و هدر webhook |
| `MINIAPP_SHORT_NAME` | نام کوتاه مینی‌اپ در BotFather |
| `MINIAPP_BASE_URL` | آدرس عمومی HTTPS سرویس `web` |
| `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS` | تنظیمات معمول جنگو |

**polling یا webhook؟** برای توسعه `WEBHOOK_URL` را خالی بگذارید. در production یک reverse proxy با TLS
(مثل Caddy یا nginx) جلوی پورت ۸۴۴۳ سرویس `bot` بگذارید و `WEBHOOK_URL=https://bot.example.com` بدهید.

## مینی‌اپ آرکید (HTTPS و دامنه)

بازی‌های آرکید داخل خود تلگرام باز می‌شوند و **به HTTPS و دامنه نیاز دارند**.

1. سرویس `web` (پورت میزبان `WEB_PORT`، پیش‌فرض ۸۱۲۰) را پشت یک دامنه با TLS قرار دهید، مثلاً `https://game.example.com`.
2. در BotFather: `/newapp` ← انتخاب ربات ← عنوان و توضیح ← آدرس وب‌اپ: `https://game.example.com/arcade/`
   ← نام کوتاه (مثلاً `arcade`). همین نام را در `MINIAPP_SHORT_NAME` بگذارید.
3. `MINIAPP_BASE_URL=https://game.example.com` و دامنه را به `ALLOWED_HOSTS` و `CSRF_TRUSTED_ORIGINS` اضافه کنید.

تا وقتی `MINIAPP_BASE_URL` یک آدرس `https://` نباشد، ربات بازی‌های آرکید را در منوی `/game` پیشنهاد نمی‌کند
(زیر منو می‌نویسد که بعد از راه‌اندازی مینی‌اپ فعال می‌شوند) و `/arcade` می‌گوید آرکید راه‌اندازی نشده است؛
۱۱ بازی داخل گروه بدون این تنظیم هم کار می‌کنند. سوپرادمین همان‌جا راهنمای سه‌مرحله‌ای راه‌اندازی را می‌بیند.

در گروه دکمه‌ی `web_app` کار نمی‌کند؛ برای همین ربات دکمه‌ی URL با لینک مستقیم می‌فرستد:
`https://t.me/<bot_username>/<app_short_name>?startapp=<match_token>` و خود مینی‌اپ از `start_param` می‌فهمد
مربوط به کدام مسابقه است. تمرین آزاد (بدون سکه) با `/arcade` در پیوی و دکمه‌ی `web_app` باز می‌شود.

**توسعه‌ی محلی با تونل:**

```bash
python manage.py runserver 8000
cloudflared tunnel --url http://localhost:8000     # یک آدرس https موقت می‌دهد
```

آدرس تونل را در `/newapp` (یا `/myapps` ← Edit) و `MINIAPP_BASE_URL` بگذارید.
برای دیدن صفحه‌ی بازی در مرورگر معمولی بدون تلگرام: `DEBUG=True` و `ARCADE_DEV_AUTH=True` و سپس
`http://localhost:8000/arcade/?dev_user=1` (هرگز در production روشن نکنید).

## دستورات ربات

**پیوی:** `/start` · `/me` (پروفایل) · `/daily` (جایزه‌ی روزانه) · `/invite` (دعوت دوستان) · `/shop` (فروشگاه ظاهری) ·
`/history` (۲۰ تراکنش آخر) · `/arcade` (تمرین آزاد) · `/gtop` (رتبه‌بندی سراسری) · `/help`

**گروه:** `/game` (ساخت مسابقه) · `/top` (امروز / هفته / کل) · `/me` · `/rules` (قوانین کلی و قوانین هر بازی) ·
`/cancel` (سازنده یا ادمین)

`/start` در پیوی یک منوی دکمه‌ای هم می‌فرستد (افزودن ربات به گروه، جایزه‌ی روزانه، پروفایل، تمرین آرکید، فروشگاه،
دعوت، قوانین، راهنما)؛ هر دکمه همان کار دستور هم‌نامش را می‌کند.

**ادمین گروه:** `/settings` — فعال/غیرفعال کردن بازی‌ها، حداقل و حداکثر ورودی، زمان عضوگیری پیش‌فرض،
اجازه‌ی ساخت بازی به همه. ادمین بودن در هر کلیک با `getChatMember` بررسی می‌شود.

**سوپرادمین:** `/grant <آیدی یا @username> <مقدار>` · `/ban` · `/unban` · `/broadcast <متن>` (یا ریپلای روی یک پیام) · `/stats`

### چرخه‌ی مسابقه

`/game` ← انتخاب بازی ← ورودی (رایگان تا ۱۰۰۰ سکه، در محدوده‌ی گروه) ← تقسیم جایزه ← زمان عضوگیری ← **لابی**
(لیست زنده‌ی بازیکن‌ها، pot و زمان باقی‌مانده) ← اجرا ← رتبه‌بندی و پرداخت.

- بازیکن کافی نیاید یا مسابقه لغو شود ⇒ **برگشت کامل ورودی‌ها**.
- در هر گروه فقط یک مسابقه‌ی فعال (قفل Redis + constraint دیتابیس).
- بعد از ری‌استارت: لابی‌ها و مسابقه‌های آرکید ادامه پیدا می‌کنند؛ بازی متنیِ نیمه‌کاره لغو و ورودی‌ها برمی‌گردد. هیچ سکه‌ای گم نمی‌شود.

## اقتصاد سکه و قوانین تراکنش

- هدیه‌ی ثبت‌نام ۱۰۰۰ سکه، جایزه‌ی روزانه با streak (۲۰۰ تا ۷۰۰؛ یک روز جا بماند صفر می‌شود)،
  سکه‌ی نجات (موجودی صفر، روزی یک بار با `/daily`)، دعوت دوست، دستاوردها، هدیه‌ی سوپرادمین.
- هر تغییر موجودی **فقط** از `wallet.services.apply_transaction(user, amount, type, idempotency_key, match=None)`:
  اتمیک، با `select_for_update` روی ردیف کاربر، هرگز منفی نمی‌شود (چک کد + `CHECK constraint`)،
  و `idempotency_key` یکتا جلوی کسر/پرداخت تکراری (کلیک دوباره، retry) را می‌گیرد.
- ledger (`CoinTransaction`) فقط اضافه می‌شود؛ ویرایش و حذف در مدل و پنل ادمین بسته است.
- بررسی تطابق جمع ledger با موجودی:

```bash
python manage.py audit_wallets
```

مقادیر اقتصاد در `config/settings.py` قابل تنظیم‌اند.

## ضدتقلب بازی‌های آرکید

کد سمت کلاینت قابل دستکاری است، پس **امتیاز هرگز از کلاینت پذیرفته نمی‌شود**:

1. `initData` تلگرام با HMAC و `BOT_TOKEN` اعتبارسنجی می‌شود (`arcade/auth.py`).
2. سرور برای هر تلاش یک session یک‌بارمصرف با seed و زمان شروع صادر می‌کند.
3. کلاینت **لاگ ورودی‌ها** (زمان هر تپ/حرکت به میلی‌ثانیه) را می‌فرستد.
4. سرور همان بازی را با همان seed در پایتون **دوباره شبیه‌سازی** می‌کند (`arcade/sim/<game>.py`) و امتیاز را خودش حساب می‌کند.
   منطق هر بازی قطعی است: گام زمانی ثابت، فقط محاسبات عدد صحیح، و RNG سیدشده‌ی mulberry32 که در JS و Python یکسان است.
5. بررسی‌های معقول بودن: طول بازی از زمان واقعی سپری‌شده بیشتر نباشد (ردّ لاگ‌های آفلاین)، تپ‌های سریع‌تر از حد
   انسانی (فاصله‌ی کمتر از ۵۰ms)، ساختار لاگ، مهلت مسابقه و تعداد تلاش.
6. موارد مشکوک در پنل ادمین (جلسه‌های آرکید ← فیلتر «مشکوک») فلگ می‌شوند.

محدودیت صادقانه: کسی که کد بازی را بخواند می‌تواند رباتی بنویسد که لاگ ورودیِ «معتبر و انسانی‌نما» بسازد.
بررسی‌های بالا این کار را سخت و قابل‌ردیابی می‌کنند ولی غیرممکن نه؛ برای مسابقه‌های مهم جلسه‌های فلگ‌شده را مرور کنید.

## پنل ادمین

`/admin/` — کاربران (مسدود/آزاد)، گروه‌ها، مسابقات (با اکشن **«لغو مسابقه و برگشت ورودی‌ها»**)،
ledger فقط‌خواندنی، بانک سوال/کلمات/پازل ایموجی/جمله‌های تایپ با **Import از CSV**، فروشگاه، دستاوردها،
جلسه‌ها و رکوردهای آرکید، و **داشبورد آمار** (`/admin/dashboard/`: کاربران فعال روزانه، بازی‌ها به تفکیک نوع،
محبوب‌ترین بازی، گروه‌های فعال).

### تنظیمات بازی‌ها و تعداد شرکت‌کننده

صفحه‌ی **«تنظیمات بازی‌ها»** (`/admin/games/gamesetting/`) برای هر بازی یک ردیف دارد:

- **حداقل و حداکثر شرکت‌کننده** با دکمه‌های `−` و `+` کم و زیاد می‌شود و همان لحظه ذخیره می‌شود.
  «حداقل» یعنی اگر تا پایان عضوگیری این تعداد نیایند مسابقه لغو و ورودی‌ها برمی‌گردد؛ «حداکثر» ظرفیت لابی است
  (با پر شدن ظرفیت، مسابقه بدون انتظار شروع می‌شود).
- **کلید فعال/غیرفعال:** بازی غیرفعال از منوی `/game`، تنظیمات گروه‌ها و تمرین آزاد آرکید حذف می‌شود.
- اکشن‌های گروهی: «۱ نفر/۵ نفر بیشتر یا کمتر»، «برگرداندن به پیش‌فرض»، «فعال/غیرفعال کردن».

هر بازی یک **بازه‌ی مجاز** دارد که از آن بیرون نمی‌رود: شطرنج و دوز همیشه ۲ نفر، بازی‌های شانسی حداکثر ۱۲،
زنجیره‌ی کلمات حداکثر ۲۰ و بقیه (از جمله آرکید) تا ۵۰ نفر. پیش‌فرض‌ها همان مقدارهای داخل کد هر بازی‌اند.
تغییرها روی مسابقه‌های **بعدی** اعمال می‌شوند (حداکثر ۱۵ ثانیه بعد در ربات)؛ مسابقه‌ای که از قبل ساخته شده با همان
تنظیمات خودش تمام می‌شود.

قالب CSV (ردیف اول عنوان ستون‌ها، UTF-8):

| مدل | ستون‌ها |
|---|---|
| کلمات | `word,category` |
| سوال‌ها | `category,text,option1,option2,option3,option4,correct,difficulty` (`correct` از ۱ تا ۴؛ دسته: `general` `freefire` `football` `movie` `science`) |
| پازل ایموجی | `emojis,answer,alt_answers` (جایگزین‌ها با `|`) |
| جمله‌های تایپ | `text` |

موجودی سکه از پنل قابل ویرایش نیست؛ اعطای سکه فقط با `/grant` (ثبت در ledger با نوع `ADMIN_GRANT`).

## اضافه کردن بازی جدید

### بازی متنی — فقط یک فایل

`games/plugins/my_game.py`:

```python
from games.engine.registry import register_game
from games.engine.rounds import RoundGame


@register_game
class MyGame(RoundGame):
    key = "my_game"
    title_fa = "بازی من"
    emoji = "🎲"
    description_fa = "توضیح یک‌خطی"
    rounds = 5
    round_seconds = 20

    async def begin_round(self):
        self.answer = "سلام"
        await self.ctx.send(f"{self.header()}\n\nبنویس: سلام")

    async def on_message(self, msg):
        if self.round_open and msg.text.strip() == self.answer:
            self.add_score(msg.player.user_id, 10)
            await self.ctx.send(f"✅ {msg.player.mention}")
            await self.close_round()

    async def on_round_timeout(self):
        await self.ctx.send("⏰ وقت تمام شد")
```

فایل‌های `games/plugins` خودکار بارگذاری می‌شوند و بازی در منوی `/game` و تنظیمات گروه ظاهر می‌شود.
پلاگین فقط با `self.ctx` کار می‌کند (`send`، `edit`، `send_photo`، `send_dice`، `flash`، `set_timer`، `content`، `end_game`)،
پس بدون تلگرام و با `tests/fakes.py` تست می‌شود. برای بازی غیرراندی از `BaseGame` ارث ببرید (مثل `word_chain.py`).

### بازی آرکید — دو فایل منطق (+ یک فایل رندر)

1. `arcade/static/arcade/<key>/core.js` — منطق قطعی: `newState(seed, config)`، `applyInput(state, [t_ms, ...])`، `step(state)`
   و فیلدهای `state.over`، `state.score`، `state.level`. فقط عدد صحیح، بدون `Math.random` و بدون وابستگی به فریم‌ریت.
2. `arcade/sim/<key>.py` — همان منطق، خط‌به‌خط، با `@register_simulator` و یک `demo_policy` (بازیکن خودکار برای تست).
3. `arcade/static/arcade/<key>/render.js` — رندر و افکت‌ها (هیچ منطق بازی این‌جا نباشد). قاعده‌های سرعت:
   پس‌زمینه‌ی ثابت با `env.scene(...)` و هر جزء پرجزئیات با `env.sprite(key, w, h, paint)` فقط **یک بار** کشیده
   می‌شود و در هر فریم فقط `drawImage` می‌ماند؛ متریال‌ها (چوب، فلز، چمن، کره‌ی سایه‌خورده، سایه‌ی نرم) در
   `common/art.js` هستند. در `draw` از `shadowBlur` و گرادیان تمام‌صفحه استفاده نکنید (روی گوشی فریم می‌اندازد).
4. ساخت fixture و تست تطابق:

```bash
python manage.py arcade_fixtures <key>
node arcade/jstests/parity.js <key>
pytest tests/test_arcade_parity.py
```

بازی خودکار در منوی «آرکید»، `/arcade` و تنظیمات گروه ظاهر می‌شود.

## تصمیم‌های طراحی

جاهایی که صورت مسئله مبهم بود و انتخابی انجام شد:

- **رابط پلاگین:** `on_message` و `on_callback` به‌جای `Update` خام تلگرام یک رویداد ساده (`IncomingMessage` / `IncomingCallback`) می‌گیرند تا منطق بازی‌ها بدون تلگرام تست شود.
- **تقسیم جایزه با بازیکن کم:** سهم‌های اضافه به نسبت بین رتبه‌های موجود پخش می‌شود (۶۰-۳۰-۱۰ با دو نفر ⇒ ۶۰:۳۰). گرد کردن رو به پایین و باقیمانده به نفر اول؛ جمع پرداختی همیشه دقیقاً برابر pot است.
- **تساوی:** امتیاز برابر ⇒ کسی که زودتر به آن رسیده جلوتر است؛ اگر زمان هم برابر بود سهم آن رتبه‌ها مساوی تقسیم می‌شود. تساوی صفر-صفر (مثلاً کسی بازی نکرده) pot را مساوی برمی‌گرداند ولی «برد» حساب نمی‌شود تا نشود با مسابقه‌های خالی آمار برد و جایزه‌ی دستاورد جمع کرد.
- **سازنده‌ی مسابقه** خودکار عضو لابی می‌شود (اگر سکه‌اش برسد). با پر شدن ظرفیت، لابی زودتر بسته می‌شود.
- **بازی‌های دونفره** (دوز) مرحله‌ی انتخاب تقسیم ندارند: برنده همه را می‌برد و مساوی نصف-نصف.
- **سکه‌ی نجات** با `/daily` داده می‌شود وقتی جایزه‌ی آن روز گرفته شده و موجودی صفر است؛ نوع تراکنش `RESCUE` به فهرست انواع اضافه شده.
- **دعوت دوست:** فقط برای کاربری که اولین `/start` او با لینک دعوت بوده؛ جایزه وقتی که دعوت‌شده حداقل یک بازی تمام کرده **و** حسابش ۲۴ ساعته شده باشد (در پایان بازی یا هنگام `/daily` بررسی می‌شود).
- **جدول هفتگی** از روی تاریخ محاسبه می‌شود (ساعت تهران، شروع هفته شنبه)، پس «ریست» خودکار است؛ job شنبه‌ها فقط قهرمان هفته‌ی قبل را در گروه‌ها اعلام می‌کند (و یک بار هم بعد از بالا آمدن ربات، برای جبران خاموشی).
- **بازی‌های دایس** یک پلاگین با پنج حالت‌اند. 🎲🎯🎳 امتیاز برابر مقدار دایس؛ 🏀 مقدار ۴ و ۵ و ⚽ مقدار ۳ تا ۵ یک امتیاز (گل). بعد از پایان مهلت نوبت، ربات خودش به نام بازیکن پرتاب می‌کند.
- **حدس عدد:** راهنمای بزرگ‌تر/کوچک‌تر روی یک پیام ثابت به‌روز می‌شود (نه یک پیام برای هر حدس) تا به حد ۲۰ پیام در دقیقه‌ی تلگرام برای گروه نخوریم. همه‌ی ویرایش‌ها از صف ویرایش (`bot/tg.py`) رد می‌شوند و `AIORateLimiter` هم فعال است.
- **موتور گرافیک:** Canvas خالص به‌جای Phaser (سبک‌تر، بدون وابستگی و asset خارجی). فونت Vazirmatn از CDN با جایگزین سیستم.
  همه‌ی تصویرها رویه‌ای (procedural) ساخته می‌شوند و در اسپرایت‌های کش‌شده می‌مانند؛ هیچ فایل تصویر یا asset
  بیرونی در پروژه نیست.
- **کیفیت تطبیقی:** اگر میانگین فریم در دو بازه‌ی پیاپی از حدود ۴۳ فریم در ثانیه کمتر شود، اول وضوح بوم
  (از ۲× به ۱٫۵× و بعد ۱×) و تعداد ذره‌ها کم می‌شود. این انتخاب فقط ۲۴ ساعت به خاطر سپرده می‌شود تا کندی موقتی
  (مثلاً حالت صرفه‌جویی باتری) کیفیت را برای همیشه پایین نگه ندارد.
- **تعداد شرکت‌کننده:** از پنل ادمین برای هر بازی قابل‌تنظیم است ولی از بازه‌ی مجاز همان بازی بیرون نمی‌رود
  (بازی‌های دونفره قفل‌اند). ربات تنظیمات را در حافظه نگه می‌دارد و هر ۱۵ ثانیه و همچنین درست قبل از ساخت هر
  مسابقه از دیتابیس تازه می‌کند. با ظرفیت‌های بزرگ، فهرست بازیکن‌ها در پیام لابی/جدول/نتیجه کوتاه می‌شود
  («… و N نفر دیگر») تا از سقف ۴۰۹۶ نویسه‌ی پیام تلگرام رد نشود.
- **آرکید:** seed مسابقه برای همه‌ی تلاش‌ها یکی است؛ تلاش ردشده هم از سهمیه کم می‌شود؛ خروج از صفحه یعنی پایان همان تلاش (جلوی توقف برای وقت‌کشی)؛ کلاینت ۳ ثانیه مانده به پایان مسابقه تلاش را می‌بندد تا ثبت شود. اگر همه‌ی بازیکن‌ها تلاش‌هایشان را تمام کنند مسابقه زودتر تمام می‌شود.
- **فلگ در برابر رد:** لاگ خراب، «سریع‌تر از زمان واقعی» و تپ‌های غیرانسانیِ زیاد **رد** می‌شوند؛ اختلاف امتیاز ادعایی با محاسبه‌ی سرور، چند تپ خیلی سریع، یا بازی آهسته‌شده فقط **فلگ** می‌شوند (امتیاز محاسبه‌ی سرور معتبر است).
- **مرحله‌های «سیخ‌زن»:** الگوهای رفت‌وبرگشتی نامتقارن‌اند تا همه‌ی محیط دایره در دسترس باشد؛ تست `test_every_handmade_and_procedural_level_is_solvable` حل‌پذیری هر مرحله را بررسی می‌کند.
- **اکشن لغو در پنل ادمین** مستقیم در دیتابیس اجرا می‌شود و ربات حداکثر ۱۵ ثانیه بعد اجرای زنده‌ی همان مسابقه را متوقف و در گروه اعلام می‌کند.
- **شطرنج:** موتور قوانین را خودمان نوشته‌ایم (`games/chess/engine.py`، بدون وابستگی خارجی) و با اعداد مرجع perft تست شده. ارتقای پیاده خودکار به وزیر است؛ هر حرکت ۹۰ ثانیه وقت دارد و تمام شدن وقت یعنی باخت. صفحه همیشه از دید سفید نمایش داده می‌شود.
- **تصویرهایی که ربات می‌فرستد:** صفحه‌ی شطرنج (چوبی، با مهره‌های استانتون حجم‌دار) و برگه‌ی مسابقه‌ی تایپ کاملاً با Pillow و رویه‌ای کشیده می‌شوند؛ مهره‌ها به فونت نمادها وابسته نیستند (`games/chess/pieces.py`). صفحه‌ی شطرنج JPEG است تا هر حرکت سریع بارگذاری شود.
- **کارت نتیجه:** در پایان هر مسابقه (متنی یا آرکید) ربات یک کارت تصویری می‌فرستد: سکوی سه‌نفره با مدال، نام، امتیاز و جایزه‌ی هر نفر (`bot/cards.py`)، و متن کامل نتیجه کپشن همان عکس است. اگر متن از سقف کپشن تلگرام بلندتر باشد کارت جدا و متن زیر آن می‌آید؛ اگر ساخت یا ارسال تصویر نشد (مثلاً فونت روی سرور نبود) فقط همان متن فرستاده می‌شود. ایموجی و نویسه‌هایی که فونت ندارد از نام‌ها حذف می‌شوند.
- **دکمه‌های رنگی:** دکمه‌های اینلاین با فیلد `style` تلگرام (Bot API 9.4: `primary` آبی، `success` سبز، `danger` قرمز) رنگ می‌گیرند: «شرکت» سبز و «لغو» قرمز، گزینه‌های منو آبی، پیش‌فرض‌ها سبز، در دوز ❌ قرمز و ⭕️ آبی، و در شطرنج مهره‌ی انتخاب‌شده آبی، خانه‌های مقصد سبز و خانه‌ی زدن قرمز. همه از `bot/ui.py` ساخته می‌شوند؛ چون python-telegram-bot 21 این فیلد را نمی‌شناسد از راه `api_kwargs` فرستاده می‌شود. کلاینت‌های قدیمی دکمه را ساده نشان می‌دهند و با `BUTTON_STYLES=False` رنگ‌ها کاملاً خاموش می‌شوند. پلاگین‌های بازی به‌جای `(متن، داده)` می‌توانند `Button(متن، داده، رنگ)` برگردانند.
- **قوانین هر بازی:** هر بازی (متنی و آرکید) سه خط قانون کوتاه در `rules_fa` دارد. در بازی‌های متنی عددها از ثابت‌های همان کلاس پر می‌شوند (`{points}`، `{rounds}`، …) تا با تغییر کد، متن قوانین غلط نشود. قوانین سه جا دیده می‌شود: `/rules` (فهرست بازی‌ها و قوانین کامل هر کدام)، دکمه‌ی «📖 قوانین بازی» زیر لابی و جدول آرکید (پنجره‌ی هشدار فقط برای همان کاربر، حداکثر ۲۰۰ نویسه) و صفحه‌ی شروع مینی‌اپ (کنترل، امتیاز، پایان بازی).
- **لحن متن‌ها:** همه‌ی متن‌های ربات و مینی‌اپ خطاب دوستانه‌ی «تو» با فعل نوشتاری دارند («می‌شود»، نه «می‌شه»)؛ تست `test_texts_use_one_written_tone` جلوی برگشتن شکل محاوره‌ای را می‌گیرد. تاریخ تراکنش‌ها شمسی است («۱۹ مهر ۱۴:۳۰»).
- **پردازش هم‌زمان:** به‌روزرسانی‌های چت‌های مختلف هم‌زمان پردازش می‌شوند (`bot/concurrency.py`) تا مکث یا کندی تلگرام برای یک گروه بقیه‌ی گروه‌ها را معطل نکند؛ پیام‌ها و کلیک‌های هر چت به همان ترتیب رسیدن پردازش می‌شوند، پس «اولین جواب درست» تغییری نمی‌کند. تعداد با `BOT_CONCURRENT_UPDATES` تنظیم می‌شود.
- **نام‌های بلند:** نام بازیکن‌ها در پیام‌های بازی حداکثر ۲۴ نویسه است و فهرست نام‌ها در پیام شروع بریده می‌شود تا هیچ پیامی از سقف طول تلگرام رد نشود.
- **نمادهای بازی‌ها:** منو و صفحه‌ی شروع مینی‌اپ به‌جای ایموجی یک نماد تصویری برای هر بازی دارند که با همان جعبه‌ابزار گرافیکی کشیده می‌شود (`common/icons.js`).
- **ظاهر پیام‌ها:** پیام‌های ربات با تیتر، خط جداکننده، نقل‌قول (`blockquote`) و نوار پیشرفت متنی قالب‌بندی شده‌اند؛ همه در `core/texts.py`.
- **کش فایل‌های بازی:** آدرس `core.js` و `render.js` هر بازی یک پارامتر نسخه (`?v=`) دارد تا بعد از به‌روزرسانی، تلگرام نسخه‌ی قدیمی را نشان ندهد.
- **تنظیمات گروه:** مقادیر ورودی و زمان با هر کلیک بین گزینه‌های ثابت می‌چرخند؛ حداقل یک بازی باید فعال بماند.

## چه چیزهایی تست شده و چه چیزهایی نه

تست‌شده (`pytest`، روی PostgreSQL 16):

- wallet: همزمانی (چند کسر همزمان، موجودی منفی نمی‌شود)، idempotency، تطابق ledger، تغییرناپذیری ledger
- تقسیم جایزه: همه‌ی splitها، بازیکن کمتر از سهم‌ها، تساوی، گرد کردن (جمع = pot)
- لابی، عضویت، لغو و refund، بازیابی بعد از ری‌استارت
- نرمال‌سازی فارسی؛ منطق هر ۱۰ بازی متنی بدون تلگرام
- شبیه‌ساز هر ۱۴ بازی آرکید در برابر fixtureها؛ API مینی‌اپ (HMAC، session، ضدتقلب، rate limit)
- handlerهای ربات با Update ساختگی؛ پنل ادمین، رتبه‌بندی، قهرمان هفته، فروشگاه
- تنظیمات بازی‌ها: دکمه‌های کم/زیاد، بازه‌ی مجاز هر بازی، فعال/غیرفعال، اثر روی ظرفیت لابی و ساخت مسابقه در ربات
- دکمه‌های رنگی (فیلد `style` در JSON کیبورد)، قوانین هر بازی و سقف ۲۰۰ نویسه‌ی پنجره‌ی هشدار، منوی پیوی، یک‌دستی لحن متن‌ها، تاریخ شمسی، حفظ ترتیب در پردازش هم‌زمان

بررسی‌شده در مرورگر (نه در `pytest`): هر ۱۴ بازی آرکید یک دور کامل اجرا شدند (شروع ← ورودی تصادفی ← ثبت امتیاز)
بدون خطای جاوااسکریپت، و زمان کشیدن هر فریم قبل و بعد از بازنویسی گرافیک اندازه گرفته شد.

**تست‌نشده در محیط ساخت این پروژه** (قبل از استفاده‌ی واقعی خودتان بررسی کنید):

- اتصال واقعی به تلگرام (توکن ربات در دسترس نبود): رفتار ربات با تلگرام ساختگی تست شده، نه با API واقعی.
- `docker compose up` (Docker روی ماشین ساخت نصب نبود).
- اجرای `node arcade/jstests/parity.js` (Node نصب نبود). تطابق JS/Python به‌جای آن با اجرای همان `core.js`ها
  در موتور JS مرورگر از صفحه‌ی `/arcade/dev/parity/` تأیید شد (۸۴ از ۸۴ مورد).
- حس بازی (سختی، سرعت، کنترل لمسی) روی گوشی واقعی: منطق و رندر بررسی شده ولی اعداد سختی احتمالاً نیاز به تنظیم دارند.
- نرخ فریم روی گوشی واقعی: سرعت رندر فقط روی مرورگر دسکتاپ (با بوم هم‌اندازه‌ی گوشی) اندازه‌گیری شده است.
